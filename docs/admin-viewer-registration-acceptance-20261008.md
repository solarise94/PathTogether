# 改版案例与验收清单

日期：2026-10-08。配套主文：[用户后台、注册与 Viewer 改版设计](admin-viewer-registration-design-20261008.md)。

本文描述待实现功能的预期，不表示生产功能已通过这些检查。原型已检查文件夹导航、搜索定位、堆叠选择、模拟授权到期等交互；真正上线前必须使用真实服务端与隔离 PostgreSQL 再验证。

## 1. 统一测试夹具

全部为虚构样例；邮箱使用 example.org；ID 由当前系统正常生成，以下 A/B/S1 等只是案例中的别名。

| 对象 | 样例 |
| --- | --- |
| Admin A | 有效 owner 账号，普通会话，没有预览其他用户身份 |
| Admin B | 若生产单 enabled owner 约束不允许第二个，则使用 store 层独立主体夹具验证授权隔离，不为测试放松生产角色不变量 |
| User U1 | `reader-a@example.org`，正式用户，2026-10-08 10:20 加入 |

## 2. 用户后台案例

### U01：新用户与测试账号分开看（P1）

前置：U1/U2/H 为正式分类，D 为 Dogfood。

操作：打开用户页，切换正式用户、Dogfood、全部；把 U2 标为 Dogfood，再恢复正式。

预期：默认只显示正式用户；筛选范围与总数一致；分类立即反映，原 user_id、启用状态、切片所有权、额度和 session 不变。每次实际分类变化有 actor 和前后值审计。操作普通用户详情以外的数据不受影响。

验证：真实 API 过滤结果与 UI 一致；普通 user 直接调用分类写接口失败；重新加载仍保持分类。

### U02：加入时间与稳定排序（P1）

前置：用户至少跨三页，包含相同 created_at 的两人。

操作：默认排序翻页，再切最早优先与最近登录；切筛选后继续翻页。

预期：默认最新加入优先；同时间按稳定 user_id 顺序；无重复/遗漏；切排序和筛选会重置 cursor。last_login_at=NULL 在最近登录排序中居后。不能只对当前页 50 人重新排序。

### U03：最近登录的更新边界（P1）

操作顺序：失败密码登录 → 正确登录 → 刷新页面 → AI 请求 → 退出后重新登录。

预期：只在两次成功建立正常登录态时更新。失败、刷新、后台活动不更新；并发登录时间不倒退。P 的受限 enrollment 会话不算正常登录。

验证：真实数据库 last_login_at 与接口字段；新注册如果跳登录页，完成注册本身不写最近登录。

### U04：历史缺失数据与信息密度（P1）

操作：查看 H；分别在桌面和手机宽度打开。

预期：显示“暂无记录”，不推断“从未登录”；不出现最近活跃、7 天活跃、登录次数等未要求指标。加入时间依然保留。账户高级管理入口可达。

## 3. 注册与邀请码退役案例

### R01：邮箱验证直接注册（P0）

操作：使用全新邮箱完成表单、验证邮件、设置密码、进入正常登录/工作台。

预期：全程没有邀请码、等候邀请或激活码；只创建一个 user_id，协议证据和必要账户初始化完整。刷新/重复提交不创建第二个账号或重复额度。

验证：真实 public 注册路径，不能用 mock 直接 set session 冒充完成。

### R02：注册开关与前置失败（P0）

操作：后台关闭注册，尝试提交；重新开放后模拟缺失邮件/TLS等必要前置条件。

预期：关闭或前置失败时拒绝新注册；界面有准确状态。旧 invite 模式配置不会绕回邀请注册，不能 silent fallback 到不验证邮箱。

### R03：旧 active 用户继续使用（P0）

前置：通过历史邀请码建立且已 active 的用户拥有切片与账单。

操作：运行迁移后登录、读片、查看额度。

预期：身份、密码与资产归属保留；不会因为 activation_source=invite 就被禁用/删除/重复建号。

### R04：旧 pending 用户分流（P0）

操作：分别迁移 P 的三种变体。

预期：有可信 email_verified_at、未禁用的账号按主文推荐方案转为正常已注册；未验证变体走重新验证，不直接开通；禁用变体保持禁用。失效 enrollment session 不能取得业务权限。账户初始化幂等。

验证：先 dry-run 输出分类数量，再对隔离数据库执行两次迁移，第二次无额外用户或额度。

### R05：旧链接、旧桥和后台接口退役（P0）

操作：打开历史邀请码链接；调用旧 create/revoke/redeem API；iframe 发旧 invite 桥请求；打开尚有效的 public 验证链接。

预期：旧页面指向正常注册、旧写接口/桥方法不再执行邀请码业务；保留通用错误响应和 token 不回显约定。正常 public 链接继续按有效期工作，不因邀请码模块删除而统一失效。

### R06：旧邮件任务和测试申请（P1）

操作：让旧邀请激活邮件任务到执行时刻；处理曾附带邀请动作的测试申请。

预期：不会再发送诱导用户输入邀请码的业务邮件；旧专用任务有明确终态。public 邮件正常发送。测试申请的其他必要用途不被连带删除。

## 4. 后台上传清单与临时查看案例

### A01：元数据列表不等于读图权限（P0）

前置：A 没有对 S1 的临时授权。

操作：打开后台清单；直接请求 S1 的 thumbnail/info/tile/crop 和新旧 URL。

预期：可看到允许的上传清单信息；不能看到图像和仅查看者可读的详细内容；Viewer 搜索里也不能出现 S1 的内容。用户 U1 自己仍正常访问。

检查列表接口响应不提前带可直接访问的图片公网地址、存储路径或可复用的无限时访问令牌。

### A02：开启一小时与重复请求（P0）

操作：A 在 10:00 开启 S1；网络重试 POST；10:20 重复点同一有效授权。

预期：截止时间仍为 11:00，返回同一有效 lease，不变成 11:20。开启仅绑定 A + S1，不授予其他主体、同名 S2 或整个目录。

11:05 重放 10:00 的旧 Idempotency-Key：不能创建新租约。明确发起新开启才创建新的 lease。

### A03：到期边界（P0）

前置：S1 截止时间为 11:00，A 已打开 Viewer、缩略图缓存存在。

操作：10:59:59 读取；11:00:00 再读取；修改客户端时间后重试；停止后台过期清理 worker 后重试。

预期：严格按服务端 `expires_at > now()`；边界时刻开始拒绝新请求，不依赖客户端倒计时或清理 worker。当前画面与预览清空，不能因 ETag 返回 304 而继续展示被授权资源。

### A04：提前结束和多标签页（P0）

操作：A 在标签页 1 打开 S1，在标签页 2 提前结束；标签页 1 继续缩放、取缩略图、切回前台。

预期：后续读取被拒，UI 进入“临时查看已结束”；另一个标签页不需要退出整个账号。原用户及其他独立授权主体不受影响。关闭预览窗口本身不等于结束授权。

### A05：过期页面不能撤销新租约（P0）

操作：页面 1 保存 lease L1；L1 已结束，页面 2 创建 L2；页面 1 用 expected_lease_id=L1 发结束请求。

预期：冲突或明确无效果，L2 保留；刷新后展示 L2，不根据 slide_id 盲目删除当前租约。

### A06：ID 新资产与同名替换（P0）

操作：后台查看 S3（legacy_filename=NULL）；给 S1 授权；删除 S1 后重新上传同名新资产 S1-new。

预期：S3 正常列出、正常按 ID 开启；S1-new 不继承旧授权、缩略图或项目引用。S1/S2 同名时每一行操作互不影响，绝不按 basename 拼路径。

### A07：资产尚未就绪、删除与并发（P0）

操作：对 S4/S5 开启查看；并发执行资产删除与新授权。

预期：不可读资产没有可用读权限；竞态中即使授权记录已落库，资产状态门禁仍拒绝删除中资源。孤儿文件不被“开启查看”隐式建号认领。

### A08：能力不扩大（P0）

操作：仅凭临时 view 尝试给其他人创建分享、下载原文件、创建标注、查看上传者 AI 会话或发起 AI。

预期：按主文的只读默认方案拒绝；不能通过 owner 角色短路获得这些能力。若实现前明确决定保留某项能力，需补独立授权与到期测试，不用本案例默认放行。

### A09：派生 token、实例和本地缓存（P0）

操作：实例 1 开启、实例 2 读取、实例 1 结束；通过旧 run grant / plugin token / 缓存图像接口再次读取。

预期：授权范围和期限一致；失效任务不产生新的图像访问，正缓存不跨到期继续放行；机器通道不能只验证资产 ready 而漏查发起主体。

### A10：旧永久直授迁移（P0）

操作：迁移包含管理员永久 slide_view_grants 的数据库；重新登录、调用旧 visibility route、打开旧 Viewer URL。

预期：原永久授权不再作为 admin 的访问旁路；提示重新开启临时查看。旧 API 不能建立新的永久授权。用户自己的切片与非管理员合法分享关系不被清空。

## 5. Viewer 与文件夹案例

### V01：单层工具栏（P1）

操作：在 1440、1024、768、390、320px 宽度查看真实应用。

预期：顶栏不换成第二层；窄屏工具进入更多菜单且仍可达。导入、缩放、旋转、ROI、保存、语言、账号、分享与 AI 的现有能力没有因简化而丢失。图标有可访问名称，菜单 Esc 和焦点返回正确。

### V02：滑过抽出与点击打开（P1）

前置：S1 正在 Viewer 中以特定倍率显示，AI 正在显示 S1 的上下文。

操作：连续划过 S2/S3；移动到抽出的卡片本体；点击 S2。

预期：划过时只展示预览，Viewer、倍率、AI 不变；卡片命中区稳定；点击且打开成功后才切换 S2。抽出层不挡住上一叠/下一叠或文件夹返回按钮。

### V03：迟到响应和切片加载失败（P1）

操作：让打开 S1 的请求变慢，随后打开 S2；或让 S2 加载失败。

预期：旧响应不能覆盖最后的有效选择；失败有重试入口，AI 不假装已绑定未成功打开的切片。已有标注草稿按当前产品保护规则处理，不能被 hover 清空。

### V04：36/500 张切片（P1）

操作：从第一叠跳到最后一叠，搜索第 499 张。

预期：侧栏高度稳定，不要求长距离滚动；按钮边界正确，少于一叠时仍能操作。搜索覆盖全部可访问数据，图像只加载当前页/有限邻近项，不同时打开 500 张大文件。

### V05：进入、嵌套、返回和页码记忆（P1）

操作：根目录→教学切片→第 2 页→复核目录→返回教学→返回根目录→再次进入教学。

预期：目录名称和上级正确，记住教学页码；文件夹导航不切换当前图像或 AI。某目录不存在或变为不可访问时有确定的返回路径。

### V06：原项目迁移及多处引用（P0）

前置：同一 S1 已存在两个项目，项目有分享和归档状态。

操作：迁移目录结构，移动项目到父文件夹，从其中一个项目移出 S1。

预期：project ID、slide_id、分享/归档语义保留；只删除一条引用，不删文件，不影响另一项目；文件夹不是磁盘路径。失去最后一条引用的本人资产出现在未归类。

### V07：目录树并发与越权（P0）

操作：A 文件夹移动进 B，同时 B 移进 A；移动到自己的子孙；跨用户父目录；删除非空目录。

预期：不形成环、不越过所有权；按主文默认拒绝删除非空目录。共享父目录不意味着所有子资源自动公开。

### V08：上传到目录与途中删除（P1）

操作：在教学目录发起上传，上传期间删除/归档该目录，然后上传完成。

预期：资产成功发布不丢失，不重新上传计费；无法归类时出现在本人未归类并提示。失败上传没有可打开的幽灵卡片。

### V09：跨目录搜索与同名定位（P1）

操作：当前在教学目录，搜索研究资料中的 S2；S1/S2 同名；搜索后结果权限被撤销再点击。

预期：结果显示可访问路径与必要区分信息；点击按 slide_id 打开并定位目录/页码；已失权结果重新校验后拒绝，不保留其预览。无权目录名、数量不会出现在搜索摘要里。

### V10：搜索竞态、空态和折叠（P1）

操作：快速输入两个不同查询，让第一请求晚回；输入不存在的名称；关闭重开；折叠侧栏后从搜索打开结果。

预期：最终结果对应最新查询；空态不是加载失败；关闭恢复焦点；选择结果可展开并定位正确位置，仍无第二层顶栏。

### V11：触屏、键盘与减少动画（P1）

操作：触屏点击；Tab、方向键、Enter、Esc；开启 prefers-reduced-motion。

预期：核心选择不依赖 hover；触屏命中区足够且不互相遮挡；键盘能进入文件夹和返回；关闭位移后仍能预览与区分选中项。

## 6. 缩略图与分享案例

### T01：多入口发布后生成（P1）

分别用普通上传、ZIP、转码、远程导入建立资产。

预期：ready 后最终可获得真实缩略图；worker 重试不重复创建无限任务。发布提交成功、入队失败也有补偿路径。缩略图失败不导致上传文件被误删或回滚配额。

### T02：图像版本与权限缓存（P0）

用同名 S1/S2、不同荧光渲染上下文和授权已结束的请求读取已缓存缩略图。

预期：不同 ID/revision/context 不串图；先鉴权再决定缓存/304；过期访问不能靠已缓存 URL 取得图片。前端不能公开展示读取失败缓存中残留的上一张图。

### T03：生成失败与重试（P1）

模拟不支持格式、损坏文件、暂时存储错误。

预期：明确的占位状态，有界重试；不一直转圈、不伪造缩略图。能正常读片的资产不因预览失败而被禁止打开。

### S01：分享能力移入按钮（P1）

操作：选择多张本人切片，在分享浮层创建、复制、检查有效期和撤销链接。

预期：现有有效期、认领、权限、ROI策略等能力保留；分享对象不能变成“所有后台清单”。选择摘要变为“仅自己”必须对应真实权限收回。

### S02：管理员查看与用户分享独立（P0）

操作：U1 先分享 S1；A 开启/结束临时查看；U1 撤销原分享。

预期：A 的临时授权操作不修改用户分享；用户撤销分享也不通过错误的同一布尔字段改写 A 的租约。各入口按各自权限来源判断，管理员到期后不能用原来的直授残留继续读。

## 7. 验收产物

实现交付至少附：

- 数据库迁移与回填 dry-run 示例；重复运行行为。
- 相关 Python/JS/E2E 测试命令和结果，失败/未跑项目如实记录。
- 真实应用截图：单层顶栏、根目录、文件夹内抽出、搜索同名结果、后台无授权/有授权/结束三态、简化用户表。
- 一段操作录屏或浏览器自动化结果：开启临时查看→进入 Viewer→时间推进到期→后续图像访问拒绝并清屏。
- 插件 manifest 哈希/source pin 验证结果，旧 invite 桥无法调用的结果。
- 已知 Dogfood 名单未拿到时明确说明“分类功能已实现，未批量标记”，不能宣称已清理测试用户。

## 8. 建议的测试分层

| 层级 | 必测重点 |
| --- | --- |
| PG/store | 分类、登录时间、ID 清单、租约 CAS/幂等/期限、父目录约束与并发环、回填 |
| Flask/API | 身份/CSRF、list/detail 同权限、缓存鉴权、注册退役、旧路由、错误码 |
| AdminBridge | 新方法 schema、owner 权限、非法 ID、invite 白名单移除 |
| JS | hover 不换片、打开竞态、页码、搜索取消、目录状态、到期清屏、焦点 |
| E2E | 真登录→后台→Viewer 全链路；移动宽度；原有导入和分享仍可达 |

P0 失败阻止发布；P1 是本次功能与交互验收范围，也应完成后再声明本轮实现完工。无需为每个 CSS 常量写镜像断言，优先验证用户行为和真实授权结果。
