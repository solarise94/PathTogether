# 转换器支持入口与项目赞助页面设计

日期：2026-10-21；更新：2026-10-22。

状态：设计约束。`release-20261021` worktree 已有官方接口赞助订单实现，当前处于代码复核与沙箱验收阶段，尚未正式开通收款。

接入约束：自愿赞助也通过支付宝官方收款接口建立订单并确认支付结果。此前“先展示现有个人收款二维码或转账链接，后续再接 API”的方案已撤回，不作为实施依据。

## 目标与范围

在本地切片转换器 `/tools/slides` 增加“支持项目”入口，并提供可直接访问的 `/support` 页面。用户可以自愿支持转换工具与 HistoPilot 套件的持续开发、维护和服务器开销。

首个可收款版本即包含官方接口下单、持久化订单、支付宝收银台、通知验签与补偿查单。页面不直接挂个人收款码或个人转账链接。若官方收银台提供扫码体验，二维码由该笔官方订单的收银台提供，不配置静态收款图片。

赞助无需注册平台账号，不兑换 AI 额度、存储、转换次数或优先处理权益。本地转换与保存继续免费使用。

本期入口放在转换器，不扩展到首页、工作台或 AI 对话面板。页面由 PathTogether 提供；HistoPilot 导航服务无需接入收款逻辑。

## 转换器入口

入口位于转换器页脚，与转换、上传、保存等操作分开。使用低强调的文字链接，避免在任务过程中弹窗或要求用户选择金额。

建议文案：

> 这个工具对你有帮助？欢迎支持项目的持续开发。
>
> 支持项目 ↗

链接指向本站 `/support`，使用新标签页打开，设置 `target="_blank"` 和 `rel="noopener noreferrer"`，并提供“新标签页打开”的可访问说明。原转换器标签页保留任务与进度，点击链接不触发取消、保存、上传或清理。

转换器不预加载支持页、不提前下单、不嵌入第三方支付脚本。支持入口在用户点击之前不增加网络请求；本页与转换引擎加载后的离线转换能力保持不变。离线时支持页可能无法打开，这不影响原标签页继续转换。

现有“本地与隐私”说明需要补充一句：主动打开支持页会访问网站；提交赞助订单后会进入支付宝收银台。原有关于“仅转换并保存”以及主动上传的边界继续保留，不把支持操作归入上传授权。

## 支持页面

`GET /support` 无需登录，可收藏、复制和直接访问；服务端渲染基础内容，复用现有字体、颜色、间距及语言切换方式。

页面按以下顺序组织：

1. **标题与用途**：“支持项目”，说明资金用于转换工具、HistoPilot 套件的开发、维护及服务器开销。
2. **自愿支持说明**：本地转换与保存免费，支持金额由用户自愿决定，支持行为不兑换平台额度或功能权益。
3. **赞助金额与下单**：收款能力就绪时展示金额选择与“通过支付宝支持”按钮。金额档位和自定义金额范围在实施时确定，由服务端发布与校验。
4. **官方收银台**：用户提交后，服务端创建赞助订单并调用官方网页收款接口，浏览器进入支付宝收银台。电脑与手机端的具体支付呈现按所选产品的实际能力验收，不自行拼装个人收款链接或二维码。
5. **联系与返回**：提供现有联系邮箱，以及“打开本地切片工具”和“返回主页”链接。提示已有任务仍在原转换器标签页中，避免让用户误以为重新打开工具会接管原任务。

支付返回后展示该笔订单的服务端确认结果。尚未收到有效通知、且查询未确认时，显示“正在确认支付结果”，不得因为跳回网站就显示成功。首期不展示公开赞助名单、累计金额或未经核实的赞助人数，也不设置“我已支付”按钮。

建议核心说明：

> 如果本地切片工具或 HistoPilot 对你有帮助，欢迎自愿支持项目的持续开发与维护。
>
> 本地转换与保存免费使用。支持项目不会增加 AI 额度或开通额外功能。

## 官方接口与赞助订单

使用已安装 `alipay-aipay` Skill 的 **AI 网页应用收款** 路线。按版本 1.7.5 的本地接口契约，电脑网页和手机浏览器均使用 `alipay.trade.page.pay`；Python 服务端通过官方 SDK 的 `page_execute` 生成支付表单，浏览器提交至支付宝收银台。

支付流程：

1. 用户访问 `/support`，选择金额并主动提交。单纯访问页面不创建订单。
2. PathTogether 校验 CSRF、请求频率、金额精度及允许范围，生成唯一 `out_trade_no`，先在 PostgreSQL 持久化待支付订单。请求幂等键在订单待支付、已支付、已关闭或即将过期时均保持与原订单绑定；重复请求返回原订单结果或明确拒绝，不因状态或剩余时间变化自动生成第二笔可支付订单。用户重新发起赞助时使用新的操作键。
3. 服务端使用订单中的权威金额、标题和支付配置调用官方 SDK，返回收银台跳转页。金额以分的整数或 Decimal 处理，不经浮点数中转。
4. 支付宝向 `notify_url` 发送通知。服务端验签并核对应用、收款方、订单号、金额和事件类型，以事务方式幂等更新订单，提交成功后返回纯文本 `success`。
5. 浏览器回到 `return_url` 的结果页，只读取本站服务端订单状态。通知未到达或结果不确定时，由服务端通过 `alipay.trade.query` 补偿查询，再更新并展示结果。
6. 未付款、已关闭和退款分别记录，退款或关闭通知不得将订单重新置为已支付。服务端补齐交易关闭、退款及退款查询能力，退款操作仅向有权限的管理方开放。

订单至少保存内部订单标识、商户订单号、金额与币种、支付环境及配置引用、订单状态、支付宝交易号和时间戳。通知处理保留必要的去重标识，退款单独记录退款请求号及处理状态；不把退款状态压成“未支付”。订单与 AI 用量账本分开存储，支付成功不触发额度调整。

退款发起方在首次提交前持有稳定的操作键，网络重试复用原退款。退款结果不确定时继续占用金额；查单确认原退款成功后，当前重试只返回原退款结果，不再顺带新建退款。进程退出可能留下 `requested` 行，这类未完成记录也须恢复或阻塞处理，不能只检查 `unknown`。同一订单的额度校验、退款预留与状态变更按一致的锁策略执行。

网页、补偿任务与运维 CLI 在生成支付表单、查询、关闭和退款前，都核对订单与配置的 `mode`、`app_id`、`seller_pid`。查询推进已支付状态前还需校验金额，运维入口不得绕过网页已有的检查。

匿名赞助订单使用当前会话或独立的安全访问凭据约束查询权限。仅知道订单号不能查询他人的赞助信息；退款操作不向匿名用户开放。

## 配置与未开通行为

支付配置包含环境、应用 ID、预期收款方、支付宝验签公钥、应用签名凭据引用、通知与回跳地址，以及允许的赞助金额。具体变量命名在实施时按项目约定确定，沙箱与生产配置和订单严格区分。

签名凭据仅由受控服务端使用，不进入页面、仓库、日志或聊天。正式接入按 Skill 的密钥流程操作，不在本轮生成或索取生产私钥。

正式收款须完成适用于实际赞助业务的产品开通，以及生产配置和支付链路验收。支付开关关闭或配置不可用时，`/support` 保留项目说明、小猫互动和联系入口，隐藏支付表单；直接访问下单接口也应拒绝。不得退回个人收款码或转账链接作为兜底。沙箱仅供开发验收，不作为面向公众的正式赞助入口。

当前继续复核已有实现；用户本人沙箱付款、生产公网通知联调与生产收银台跳转链验证仍待完成。签约入驻按用户后续安排推进；代码测试或沙箱通过不代表正式收款已开放。

## 页面边界

支持页不读取切片文件、文件名、哈希、缩略图、转换任务或 OPFS，也不携带这些信息进入支付订单。支付宝在用户主动进入收银台后处理支付所需信息。

说明页沿用公开页面的安全响应头，提供中英文文案及键盘焦点。独立支付跳转页按官方 SDK 的实际表单输出制定 CSP，只允许当前环境的支付宝网关；原转换器的 CSP 不变。基础说明可在 JavaScript 不可用时阅读。

赞助下单保留 CSRF 和频率限制。支付宝通知端点只精确豁免登录与浏览器 CSRF 校验，使用官方 SDK 验签及业务字段校验作为接收依据；不得给整个 `/support` 或 `/api/support/` 路径族批量豁免。

订单、回跳结果页及支付响应不经共享缓存，不向第三方发送订单访问凭据；日志避免记录签名凭据、完整回调正文和付款人敏感信息。

## 产品依据与开通条件

Vibe Pay 基础收款能力提供支付、查询、退款等接口，订单及业务流程由应用维护。[产品文档](https://aipay.alipay.com/docs/vibe-pay.html)

本方案按本机 `alipay-aipay` Skill 1.7.5 的网页收款、通用交易与异步通知契约设计。Skill 没有为纯赞助单列准入结论；正式开通前，应按真实业务说明核实可用产品和经营类目。采用官方接口是本项目确定的接入约束，不能据此推定业务审核已通过。

不将官网文章中“参考现有收款产品”的描述解释为允许本项目直接挂个人收款码的依据。

## 实施验收

以下为后续代码实现的验收项，本轮文档编写不执行支付或转换测试。

| 场景 | 预期结果 |
| --- | --- |
| 未登录访问 `/support` | 正常显示说明，无登录跳转 |
| 支付配置缺失或正式收款未开通 | 保留说明与联系入口，禁用下单，不展示个人码或转账链接 |
| 主动提交赞助 | 服务端校验金额并持久化订单，通过官方接口进入收银台 |
| 重复提交或非法金额 | 所有订单状态下同键返回原操作或明确拒绝；不重复建单、不接受越界或精度错误的金额 |
| 已支付或剩余不足五分钟时重放旧表单 | 不自动创建替代订单，新的赞助意图必须使用新操作键 |
| 转换进行中打开支持页 | 新标签页打开，原任务不被取消或重建，可继续保存 |
| 未点击支持入口 | 无支持页、支付服务或追踪请求 |
| 离线转换时点击入口 | 支持页加载失败不影响转换器继续运行 |
| 中英文及窄屏访问 | 文案完整，金额选择与收银台流程可操作，无横向溢出 |
| 键盘访问及禁用 JavaScript | 支持入口可聚焦，页面基础说明可读 |
| 无效签名或业务字段不匹配 | 拒绝通知，不更新订单为已支付 |
| 重复、迟到及退款通知 | 持久化幂等，不重复记账、不把退款误认成新付款 |
| 浏览器回跳或通知丢失 | 以服务端确认结果展示，必要时官方查单；不信任回跳参数 |
| 官方查单超时或未知状态 | 保留待确认状态，允许后续补偿，不误报支付成功或失败 |
| 订单查询与退款权限 | 匿名订单仅凭合法访问凭据查询，管理方鉴权后才可退款 |
| 支付关闭、退款及退款查询 | 官方结果与本地状态可追溯，无重复退款 |
| 退款超时后重试且查单确认原退款成功 | 返回原退款结果，不创建第二个退款请求号 |
| 退款调用过程中进程退出 | 恢复 `requested` 行，不在未核实原退款前发起新退款 |
| 并发首次请求触发限流桶创建 | 每次请求均计入次数，达到阈值正确锁定 |
| 运维 CLI 查询或关闭其他配置的订单 | 拒绝调用支付宝及修改本地状态；同配置查单也校验金额 |
| 沙箱与生产环境 | 配置、订单、网关和验签上下文严格隔离 |
| 支持页面与 AI 额度 | 不开户、不充值、不调整额度，不展示未经确认的到账状态 |
| 支付跳转与页面安全头 | 官方 SDK 表单可用，不放宽转换器 CSP，不接受任意跳转地址 |

实现后复用 `tests/test_slide_tools_page.py` 和公开页面测试惯例，并补充订单、验签、幂等、权限、查单补偿及退款检查。浏览器检查覆盖真实转换进行时的新标签页操作，以及真实沙箱收银台付款；静态扫描和返回支付表单不等于支付测试通过。
