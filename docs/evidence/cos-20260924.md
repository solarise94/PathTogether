## 7. 2026-09-24 授权裁决

版本控制已由操作者开启。探针 PUT 返回 `x-cos-version-id`（长度 27），按 versionId 的 HEAD 为 200，按 versionId 的 DELETE 为 204。

### 7.1 候选 B：失败（§3.0 条件 3）

对同一 key 签发一张仍在有效期内的单 key STS，假定预约 64 字节：

|---|---|
| STS PUT 2000 字节 | 200，带版本号 |

| 长期密钥按 versionId HEAD | 200，Content-Length 2000 |

条件 1、2 此前已成立，条件 4 的钉版本机制也成立。条件 3 不成立：凭证有效期内可以堆出超过预约的历史版本，事后能删掉不算通过。因此不实现 `B-SDK-STS`，不暴露 `/credentials`。

### 10.6 组件复用原则更新与官方 SDK 切换（2026-09-25，用户改 D2 后执行）

用户于实现进行中更新了[分流文档](../upload-routing-open-source-review.md) D2/§3（组件复用原则 2026-09-25）：**生产不自研签名算法，协议层优先官方 SDK；PoC 手写签名只用于实验**。据此：

- `requirements.txt` 新增 `cos-python-sdk-v5>=1.9.44`（venv 实装 1.9.44）；
- `cos_client.py` 由"PoC 签名逐句移植"**重写为官方 SDK 薄适配**（仅保留配置注入/接口归一/异常脱敏；函数签名不变，worker 与控制 API 无感知切换）；
- 按新原则对官方 SDK 在专用测试桶**重新验收**（§10.6 表；对应用户要求的"长度绑定需重新验收"）：

| 用例（1 MiB 分块，SDK 预签名绑定 Content-Length） | 结果 |
|---|---|
| 精确长度 1,000,000 PUT | 200 |
| 超长 +1 字节 | 403 `SignatureDoesNotMatch` |
| 截短 −1000 字节 | 403 `SignatureDoesNotMatch` |
| 篡改 partNumber（1→2） | 403 `SignatureDoesNotMatch` |
| 预签名查询改作 GET | 400 `InvalidArgument` |
| TTL 1s 签名 +70s 重放 | 403 `AccessDenied` |
| Complete 响应含 `x-cos-version-id` | 是（head 复核版本+Content-Length 一致） |
| Range GET（bytes=10-19/100） | Content-Range 正确，流式读 10 字节 |
| 真实浏览器 PUT（Chrome 153，本地 8765 真实页面，不绕过 CSP） | 200，ETag 可读；Abort 204（SDK 签名 URL 过页面 CSP + 桶 CORS） |

验收后清场：`poc/` 版本 0、进行中 multipart 0（过程中两处探针遗留 uploadId 均 Abort）。首轮探查曾因 SDK `get_presigned_url(Bucket, Key, Method)` 参数序误用产生一次 400（Appid 头缺失）与一处未收口 multipart，已修正并计入清场。§7 的 A 裁决证据（PoC 手写签名）保留为历史实验证据；生产实现的绑定语义以本节官方 SDK 验收为准。
