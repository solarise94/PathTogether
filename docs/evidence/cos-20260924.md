### 2.2 COS 签名算法交叉验证（离线，无网络）

- 将 `tools/cos_xml_signing.py` 与官方 cos-js-sdk-v5 `server/sts.js` 的 `put-sign`
  参考实现（Node 逐句移植）在固定输入下对比：3 个用例（仅 host / 含
  partNumber+uploadId / 绑定 content-length）的 `q-signature` **逐字节一致**。
- 已知无害差异：官方 JS demo 用小写 method 参与 FormatString（`'put'`），本实现用
  大写（与官方 Python SDK 及 urllib 实际发送一致）；两参考实现在同一 case 下分别
  与本实现完全一致，COS 侧对 method 大小写不敏感（demo 小写签名在官方文档流程中可用）。

### 2.3 依赖隔离验证

- `experiments/cos-poc/.venv`（gitignored）+ `pip` 引导（系统缺 ensurepip，用
  `venv --without-pip` + `bootstrap.pypa.io/get-pip.py`，产物全部在 .venv 内）。
- 安装并 import 验证：`numpy 2.5.3`、`requests 2.34.2`、`qcloud-python-sts 3.1.6`
  （`from sts.sts import Sts` OK）。产品 requirements 未改动。

### 2.4 STS 签发器（dry-run，无网络）

- `COS_POC_BUCKET=demo-1250000000 COS_POC_REGION=ap-guangzhou python3 tools/sts_issuer.py --dry-run`
  渲染出的策略：resource **精确到单对象**
  `qcs::cos:ap-guangzhou:uid/1250000000:demo-1250000000/poc/obj-…`，action 仅
  PutObject/Initiate/UploadPart/Complete/ListParts/Abort（无 GetObject/Delete/
  GetBucket/ListMultipartUploads）——与 §3.0 条件 1/2 对齐。
- 无凭证运行：退出码 2，报 `blocked_external_input`，列出全部缺失环境变量，无网络调用。

### 2.5 测试文件生成器实跑

- os.urandom 回退路径（系统 Python 无 numpy）：
  `--sizes 1048576` 生成 1048576 字节，`--verify` 尺寸与 SHA-256 均匹配（0 failures）。
- numpy 路径（.venv，`--seed 12345`）：1048576 与 2000000 字节两文件生成 + verify
  通过；同种子复跑 SHA-256 一致（`e4ff6850ec95e4fc…`），manifest 记录方法/种子/块大小。
- 冒烟尺寸 1048576（1 MiB）仅验证脚本可用性；合同测试尺寸为十进制 300000000/500000000
  （必测）、2000000000（条件追加）、约 9500000000 边界。
