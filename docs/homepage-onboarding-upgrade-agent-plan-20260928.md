# 主页使用引导升级：Agent 执行方案

日期：2026-09-28。范围：PathTogether 主页、既有认证入口的引导及工作台首次使用衔接。本文为待实施方案。

## 1. 用户目标与设计裁决

用户反馈：新访客不清楚注册、登录、进入工作台和上传之间的关系；首屏右侧组织示意不能帮助理解真实软件；工作台入口只在右上角，首屏正文虽提示已登录，却没有相邻操作。

按用户提供的两张截图实施以下裁决。截图是问题与布局参考，红框不是最终页面装饰，截图里的文字也不是额外执行指令。

1. 首屏保留“直接体验 Demo”，紧邻增加未登录态的“登录工作台”或已登录态的“进入工作台”。工作台入口为唯一强视觉主按钮，Demo 为次按钮，两者均清晰可见。
2. 未登录时在按钮下直接展示“没有账号？注册账号”，无需用户先打开登录弹窗寻找注册。注册受限模式改为符合实际政策的入口与解释。
3. 红框区域替换为真实内部工作台截图；无法取得合适公开示例时，用严格对应现有界面的 SVG 工作台示意。不是换另一张组织插画。
4. 顶栏右侧保留语言切换和一个账户头像按钮；工作台/退出等放到账户展开面板中，主使用入口留在 Hero。
5. Hero 后、更新内容前增加简洁“如何开始”，把真实用户旅程讲清楚；对首次进入工作台的空列表补一个实际可用的上传/示例入口，形成闭环。

保留现有深色风格、品牌和主要产品内容。本轮不是重新做品牌、重写认证、修改注册审核策略或上线 COS。所有上传文案跟随当前能力，用户流程里不出现 COS/V1/V2 等实现名称。

## 2. 已查阅的设计依据

资料于 2026-09-28 查阅。以下区分通用建议与本项目裁决；不要宣称某条设计系统规定所有网站都必须如此布局。

| 来源 | 相关原则 | 本项目采用方式 |
|---|---|---|
| [NN/g：Homepage Design — 5 Fundamental Principles](https://www.nngroup.com/articles/homepage-design-principles/) | 首页应表达用途，通过具体例子展示内容，并明确用户下一步；避免无信息价值的装饰 | 使用工作台预览，按钮标明目的地，使用流程前置 |
| [GOV.UK：Button](https://design-system.service.gov.uk/components/button/) | 多个同等主要行动会削弱重点；按钮文字说明实际动作 | 工作台是主行动，Demo 是次行动；不摆两个同样高亮的大白按钮 |
| [GOV.UK：Create accounts](https://design-system.service.gov.uk/patterns/create-accounts/) | 区分创建账户与登录，说明创建过程；仅把选项并排放置并不足够 | 首屏提供注册文字入口，并解释验证/审核条件；登录与注册弹窗标题、文案明确区别 |
| [W3C Design System：SVG icons](https://design-system.w3.org/styles/svg-icons.html) | 带文字图标更少歧义；纯图标需要可访问名称 | 按用户要求简化为头像，但提供“账户菜单”等名称；主要工作台入口仍有可见文字 |
| [WAI APG：Disclosure](https://www.w3.org/WAI/ARIA/apg/patterns/disclosure/) | 展开控件用按钮、表达展开状态并支持键盘 | 账户面板采用普通 disclosure，包含原生链接/表单；不随意套 menu/menuitem 角色 |
| [WCAG 2.2：Target Size (Minimum)](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html) | 指针目标有尺寸/间距要求，存在适用例外 | 本项目头像与主操作自定至少 44×44 CSS px；这是高于常见最低尺寸要求的设计目标，不冒称标准统一要求 44px |

“登录工作台”作为本项目中文文案、Demo 与工作台并排、真实工作台截图优先，均为结合用户诉求的设计判断。指南支持明确引导，并未指定这些具体措辞。

## 4. 首屏布局和文案

桌面结构示意（定位关系，不是要求固定像素）：

```text
品牌   产品 / 如何开始 / 更新 / 其他链接                       EN  [头像]

与 AI 一起，观察病理切片。          [真实工作台预览]
在工作台上传切片，查看、标注，        切片列表 | 查看区域 | AI / 标注面板
并使用 AI 导航与分析工具。

[直接体验 Demo · 次按钮] [登录工作台 · 主按钮]
Demo 无需登录；上传自己的切片请先登录工作台。
没有账号？注册账号

如何开始
① 注册账号  →  ② 登录工作台  →  ③ 上传切片  →  ④ 查看与分析
（验证/审核要求按实际模式显示）
```

主标题可以保留现文案，说明文字减少抽象能力堆叠，以“在工作台上传并使用自己的切片”为核心；不虚构 AI 功能或承诺自动诊断。保留已有研究用途边界，不额外塞入大段免责声明。

### 4.1 状态矩阵

| 服务端状态 | Hero 主入口 | 辅助入口/说明 | 账户头像行为 |
|---|---|---|---|
| 未登录、public | 登录工作台 → `/login?next=/app` | Demo → `/demo`；“没有账号？注册账号”→ `/register` | 通用用户图标，展开“登录工作台 / 注册账号” |
| 未登录、email_verify | 同上 | 注册/申请入口；说明邮箱验证、设置密码及审核通过后使用的实际顺序 | 同模式的登录/申请入口 |
| 未登录、invite_only | 同上 | “有邀请码？注册账号”；说明需邀请码，不宣传开放注册 | 登录与邀请码注册 |
| 未登录、closed | 同上 | “已有账号可登录；暂未开放注册”，Demo 仍可用 | 只给实际可用入口，不出现可提交注册动作 |
| 已登录且可访问工作台 | 进入工作台 → `/app` | Demo 为次入口；“上传切片，继续查看、标注与协作”，不再提示注册 | 用户首字/现有头像；展开身份摘要、工作台、退出 |
| 待审核/未激活/被禁用 | 严格按既有后端登录与权限合同 | 告知实际状态和下一步；不显示“现在上传”或通过前端伪装可用 | 如无合法会话按未登录处理，错误信息不泄露他人账号状态 |
| 本地免登录 | 保留既有直达工作台路由 | 若独立预览介绍页，入口应为进入工作台，不要求虚构登录 | 不显示无意义退出/注册 |

“如何开始”使用四步短说明；第一步根据注册模式解释邮箱验证或邀请码，审核模式显式包含等待批准。不要把异步审核隐藏成“注册即用”。不在首屏增加第三个同级大按钮；注册入口使用清晰文字链接。

优先让用户在常见桌面首屏同时看到标题、两个入口和注册提示；手机按“说明→入口→注册提示→预览→流程”顺序，不能把操作推到巨大图片后面。无需强行在所有小屏幕塞下四步。

## 5. 预览图的制作合同

### 优先：真实界面截图

在独立本地测试环境，用许可明确的公开示例/合成切片和测试账户截取当前 `/app` 的真实界面。画面必须能辨认软件的三个部分：切片列表/上传入口、实际查看区域、已存在的 AI 或标注面板。

- 使用与默认用户角色相符的界面，不截 admin 控制台或未发布功能。不能为了好看编造分析结果、置信度或测量数值。
- 画面不出现真实邮箱、患者/研究者资料、访问 token、私有切片名称。直接用安全测试数据制作，不依赖模糊处理掩盖真实敏感原图。
- 画面取景优先保留可理解的交互区域，而非整张桌面缩小到不可读。不要铺多个密集窗口、假浏览器地址或夸张立体透视。
- 图下注明“工作台预览 · 示例切片”，截图是展示材料，不承诺其中的按钮可以直接点击。
- 可用 2–3 个 HTML 图外标注说明“上传切片 / 查看与标注 / AI 辅助”，只有真实入口使用链接。说明不要全部烘焙进图片，避免英文版无法翻译。
- 保存取景来源、代码版本、视口、示例数据来源及可复跑截图命令。静态资源放 `static/entry-media/`，测试截图放 artifacts；不提交浏览器个人配置或完整测试数据库。

### 备选：对应真实结构的 SVG

若无法在本轮获取合适截图，直接制作 repo-native SVG/HTML 示意，不阻塞等待外部设计资源。必须按真实布局表达列表、上传入口、切片视野和侧栏，文字与实际功能一致，标注“工作台界面示意”。不能把示意称为真实截图，也不能沿用当前只有组织图加四步 Agent 文案的构图。

本轮不使用 AI 生成界面截图来冒充产品。SVG 不含 script、foreignObject 或外部请求；提供适当 title/desc 或 img alt。截图/SVG 的重要说明保留 HTML 文本。整个预览不再一概 `aria-hidden=true`，也不让屏幕阅读器朗读装饰细节。

### 加载与降级

截图提供适配尺寸 WebP/AVIF 与兼容回退、明确 width/height 或 aspect-ratio；首屏主图不懒加载，其余页面演示继续按需加载。项目自定首屏预览资源预算：桌面选中资源尽量 ≤250KB、手机 ≤120KB，超出须说明画质/可读性取舍。

不自动播放重视频、不嵌 iframe `/app`、不为拍“真实界面”在访客首页加载工作台 SDK 或启动登录/COS/AI 请求。资源失败时仍保留入口与可读说明，不能整块空白撑住页面。只删除旧 Hero 专属 SVG 初始化，保留下方产品演示和 reduced-motion 行为。

## 6. 账户头像和认证衔接

头像是原生 button，`aria-label` 随语言为“账户菜单”/“Account”，`aria-expanded` 与 `aria-controls` 对应展开面板；可提供 tooltip，但 tooltip 不能是唯一名称。未登录用通用图标，已登录用现有安全头像或展示名首字，不为头像新增上传头像系统。

展开面板采用普通 disclosure：Tab 到链接/按钮，Enter/Space 开关，Escape 关闭并回到触发器；点击外部关闭；打开认证 dialog 前关闭账户面板，关闭 dialog 后焦点回到一个仍可见的触发器。避免模态叠层与关闭后焦点落到隐藏链接。

退出继续使用 POST `/logout` 和 CSRF，不能改 GET。账户资料仅在展开后简要显示，不把邮箱塞进头像 tooltip。服务端输出转义，保留 no-store/安全响应头，不能跨用户缓存展示名。

新 Hero 和面板入口复用现有 `/login`、`/register` 与 entry-auth.js。无 JS 时链接仍可深链到服务端表单；next 默认 `/app`，保留既有站内安全校验，不通过参数支持任意外站跳转。登录错误、限流、验证码/协议/审核等既有策略不因 UI 改造绕过。

登录弹窗建议标题“登录工作台”，说明“使用已有账号登录，上传并管理你的切片”；注册视图明确“创建账号”或“申请使用”的实际任务。双方均可切换，但只展示当前视图，复用原表单，不增加重复 ID、提交监听器或嵌套 form。

## 7. 从注册到上传的闭环

1. 未登录访客点击 Demo：无需先注册，进入真实示例，不改变工作台的授权规则。
2. 点击登录工作台：打开既有登录视图，成功进入 `/app`，不返回一个没有动作的首页。
3. 点击注册：按服务端模式完成协议、邮箱验证、设置密码/申请；成功页明确“下一步登录”或“等待审核”。复用返回的安全 next，不新增自动授予权限。
4. 首次登录工作台无切片：在现有空态中显示“上传你的第一张切片”并调用现有上传控件，同时提供查看示例。只补最小空态衔接，不新增另一套上传实现或强制 onboarding 遮罩。
5. 上传不可用或账号无上传权限：保留工作台访问与可用示例，给出实际原因/稍后重试，不能因首页宣传而偷偷开启 capability；不向普通用户解释 COS 配置或内部路由。
6. 上传后展示实际处理进度，结果可查看后进入切片；首页不承诺未实现的“瞬间完成”。

待实现的 [统一 COS 上传方案](cos-only-upload-agent-plan-20260928.md) 与本任务解耦：主页可以先升级，上传入口委托运行版本的权威能力。将来切换 COS 不应再次修改用户的注册/登录心智或按钮文案。

## 8. Agent 连续执行步骤

### H0：核对与基线

读取适用 AGENTS.md、git status/diff、主页及认证现状；记录四种注册模式、登录状态、默认目的地和上传能力。截图复现用户给出的两个问题。对他人未提交的认证改动做兼容性核查，必要时只增加局部上下文/词条。

### H1：素材与布局

先制作真实安全样例预览；无法取得合适截图时按第 5 节制作 SVG。实现 Hero 双入口、注册文字入口、四步流程及简化顶栏。保留原产品页结构，更新锚点；不要让“更新内容”继续挡在首次使用指南前面。

### H2：状态与认证

按第 4 节状态矩阵做服务端上下文与前端行为；复用 dialog/next/CSRF；实现头像 disclosure 与双语。清除旧“已登录请去别处找工作台”的提示、无用途头像注释与废弃 Hero 渲染代码。

### H3：工作台最小衔接

检查注册结果/验证结果的下一步，补工作台空态的真实上传入口。测试 capability off 和权限不足时文案正确；不改注册策略、角色/额度或上传链路。

### H4：浏览器与回归验收

完成第 9 节，修复发现的问题；检查现有 entry-media 演示测试没有因为删除 Hero 而误删断言或跳过功能。核对真实页面渲染和网络，不只测试静态 HTML 字符串。

### H5：交付

给出修改文件/提交、前后对比截图、状态矩阵结果、注册到上传录屏或步骤证据、真实测试命令、资源尺寸与来源。无生产部署授权，交付本地可审阅结果；不将尚未获准的真实邮箱/真实 COS 测试写成完成。

## 9. 验收与完成标准

| 场景 | 通过条件 |
|---|---|
| 首访 | 不打开菜单即可找到 Demo、登录工作台、符合模式的注册入口；说明两条路径差别 |
| 已登录 | Hero 显示进入工作台，不再要求注册/登录；头像可用、退出 POST+CSRF |
| 注册四模式 | public/email_verify/invite_only/closed 的入口与流程真实一致，不承诺未批准即可上传 |
| 认证 | Hero/头像/深链接均使用同一 dialog；错误回显、切换、焦点返回、限流和安全 next 无回归 |
| 真正新用户 | 受控测试邮箱完成注册/验证；需要审核时用测试管理员按实际流程批准；登录后能找到上传并完成一份测试切片查看 |
| 不可用状态 | 上传能力 off/账号无权限时有真实解释，Demo/其他允许功能仍可用，无隐式授权或上传回退 |
| 键盘与读屏 | 头像有名称、展开状态正确，Tab/Enter/Space/Escape 可用，关闭后焦点可见；预览有简洁描述 |
| 响应式 | 至少 1440×900、1280×720、820×1180、390×844、320px 宽和 200% 缩放；中英无横溢出，按钮不被图挤走 |
| 视觉真实性 | 主图能看出是软件及其主要区域；非真实图明确标示示意；素材没有私有资料或未实现功能 |
| 性能与稳定 | 图有固有尺寸、无明显布局跳动；下方演示继续按需加载；首页不加载工作台应用/发 AI 请求 |

新增必要行为测试，优先复用 `tests/test_phase1_auth_ui.py`、`tests/js/entry-auth.test.ts`、`tests/e2e/entry-media.spec.ts`；注册相关按实际变动运行 `test_public_registration`、`test_email_verify_activation` 等已有用例。布局/头像/新用户流程用浏览器测试；不为每条静态文案创建脆弱快照。

小型可用性验证建议让未参与设计者在无提示下回答：“不注册能做什么？上传自己的切片从哪里开始？没有账号怎么办？注册后下一步是什么？”并实际找到入口。未进行真人测试时只报告启发式检查，不编造转化率或用户通过率；不为本次改造新增未经批准的追踪 SDK。

完成标准是引导与实际流程一致、所有状态下入口可用、旧 Hero 无用代码已删除。不能只在 Demo 旁加一个登录按钮就宣布整个流程升级完成。
