- OkHttp 是通用网络客户端，原词表将它直接视为爬虫，证据不足。已移除该规则。
- 泛化 bot/crawler/spider 等匹配收窄到产品词尾，避免 RobotPhone 一类词中子串误判；保留 SomeCompanyCrawler 等实际爬虫产品名。

- “匿名访客”现在说明为“未命中爬虫规则”，不再暗示确认是真人。规则版本升到 2026-09-21.v3。

## 3. home / login 是否是本人或客户找不到入口

最近访问按时间混排所有人的公开页面请求；不包含工作台内操作，也没有真实浏览器会话标识。daily_visitor_hash 按 IPv4 /24、IPv6 /64 网段和日期轮换，同网段可能多人共用，不能作为身份或精确访问路径。

生产边缘日志给出了直接证据：

- 9 月 16 日起共 925 次 GET /login 200，该入口日志未见 POST /login。
- 第一大扫描来源：387 次 `/wp-admin/install.php` 302，随后 382 次 `/login` 200；还有 3 次该扫描路径 502。
- 另两个来源各贡献 161 次 `/login`，此前扫描 `/.env`、`/.git/config` 和各类 PHP 探测路径。
- 截图中 9 月 20 日 23:31:07、23:55:36，9 月 21 日 00:03:39 的 login，均对应第一大扫描来源前一刻的 WordPress 路径请求。

根因是 `_require_auth` 在路由不存在时仍发登录重定向。已改为不存在的路径直接 404，实际 `/app` 等受保护页面仍正常跳转登录。没有按 IP 封禁，也没有删除历史污染记录。

这足以解释大量 login，不支持“客户一直找不到登录方式”的结论。截图中零散已登录首页记录属于谁，现有匿名统计不能判定；也不能将 histopilot.com 这一入口的 POST 观察外推到另一域名。

## 4. DeepSeek 余额自动检查

旧快照：2026-09-19 10:44:48，¥474.93。排查时从生产环境请求官方端点，返回 HTTP 200，CNY **473.81**，is_available=true。此次查询未改写生产快照。

官方接口仍为 [GET /user/balance](https://api-docs.deepseek.com/zh-cn/api/get-user-balance/)，金额为十进制字符串；无需发起模型调用。

本地实现：

- 默认开启后台检查，启动时检查缺失/过期快照，之后每 5 分钟检查一次；快照满 1 小时才访问上游。
- 失败后 5 分钟重试；PostgreSQL advisory lock 和持久化检查时间避免多个 worker 同时重复自动请求。
- 成功继续使用现有 Decimal 转 nano 流程写快照。失败保留最近成功快照，不伪造零余额。
- `billing.provider_balance_auto_check` 审计记录保存检查时间、结果代码和 HTTP 状态，actor_role=system，不含密钥或供应商原始响应。
- owner 余额 GET 增加 auto_check 状态，费用页显示自动检查配置、上次时间及错误类别。原手动刷新鉴权和限速保留。
- `PROVIDER_BALANCE_AUTO_CHECK_ENABLED=0` 可关闭；测试明确关闭后台线程，使用 fake provider 验证。

余额后台检查不等于发送外部通知；没有设置邮件、聊天消息或 Codex 定时任务。
