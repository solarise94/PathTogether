过程记录：第一次 C4 全量里 `d-repeated-clicks` 失败——进行中的任务行把「继续上传」换成了
「查看上传进度」，而该用例依赖进行中行仍有（禁用的）「继续上传」做重复点击防护验证。改为
保留禁用的「继续上传」并另加「查看上传进度」后，C4 15/15、R1 31/31 重跑通过。第一次 R1
全量里 `m3` 失败是用例前置假设错误（前序 d5 场景让同一用户留有进行中上传，第一次新建即
排队）；用例改为接受两种起始状态后重跑通过。

修复前失败的演示方式：vitest 与 pytest 新用例在临时还原为 HEAD 的实现文件上运行（失败），
再恢复；浏览器 l1/m1/m2/m3 在 `git stash` 掉四个实现文件（上传控制器、工具页、i18n、
share_store_pg）后运行全部失败，n1 在还原管理插件 0.4.12（含 pin）后失败。

## 部署后真实用户验收（生产，普通测试账号，小合成文件，真实 COS）

1. 未登录在工具页本机转换 → 刷新 → 任务列表「上传到工作台」：结果面板出现，登录说明与
   链接可见可点；登录回到工具页后同一行上传，进度、取消与发布结果都可见。
2. 刷新后的任务列表上传失败/取消后可从面板或列表重试。
3. 项目内两张同原始文件名切片，界面删除其一并刷新：被删的不在列表和计数里，另一张可打开。
4. 管理插件切片页（owner）：新上传显示原始文件名与 ID，状态可读；不可用资产「加入」禁用并
   说明原因。
5. 结构化错误文案只在本地对真实端点合同复现（避免在生产制造等待上限）。
6. 清理只删本次测试创建的切片/项目与本地任务，核对远端/本地暂存清理、预约释放、原有测试
   资产不变、测试账号用量恢复。
