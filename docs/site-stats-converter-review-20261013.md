## Findings

### R1 · P2：转换工具及新增公开指南完全没有访问记录

位置：`site_stats_store.py:125`（`PAGE_ALLOWLIST`）。

目前仅包含 `/`、`/demo`、`/register`、`/login`。`/tools/slides`、`/guide`、`/guide/conversion`、`/guide/collaboration`、`/site-map` 等成功 HTML 请求在入队前就被丢弃。后台“公开落地页 Top 10”因此不会显示它们。

复现：已有 fixture 建立有效 secret 和入口域名后，`_ev(path='/tools/slides')` 返回 `None`。同样检查其他新增公开页，均不采集。

影响：无法判断转换页面访问量，也无法评估新增首页入口或指南带来的流量。这是缺少观测，不能解释成零使用。

建议：为确定的公开 HTML 页面增加固定页面键，与网站地图核对覆盖；继续拒绝分享 token、私有资源和带敏感参数的请求。仅记录页面访问无需增加浏览器额外请求。转换开始/成功/失败/导出仍需另做结果观测，不能用页面访问代替。

### R2 · P2：不同访问类别、不同入口域名共享去重键，先到的事件覆盖统计口径

位置：`site_stats_store.py:801`，`migrations/0030_site_visit_events.sql` 的 `site_visit_events_dedup_unique`。

唯一键只有 `(daily_visitor_hash, page_key, dedup_bucket)`，没有 `request_host`、`visitor_kind`。哈希本身按 IPv4 /24 或 IPv6 /64 网段生成，不区分浏览器和爬虫。

真实独立 PostgreSQL 复现：

| 输入（同页面、网段、10 分钟桶） | 应分别保留 | 实际 |
|---|---:|---|
| curl → Chrome | 2 | 仅 curl；浏览器被丢弃 |
| Chrome → Googlebot | 2 | 仅浏览器；爬虫被丢弃 |
| histopilot.cn → histopilot.com | 2 | 仅 .cn |

影响：真人/爬虫比例和域名归属取决于先到的是谁；若当前白名单排除先到的域名，后到的合法域名事件也已丢失。历史行无法可靠补回。

建议：以迁移同步扩展唯一键和 `ON CONFLICT`，至少隔离域名及浏览器/爬虫类别。是否区分匿名和登录访问、是否区分 bot 名称应明确统计定义，避免一个修改悄悄改变访问计数。相同维度内重复仍应去重，近似访客数仍按日哈希计算，不能将新增事件数当成人数。

### R3 · P2：取消保存和保存失败的本地提示会立刻被清空

位置：`static/tools/tools-slides.js:1439`（catch）及 `:1448`（finally 中的 `renderSaveStatus()`）。

成功时设置了 `page.saveMsg`，取消和失败只改 `textContent`。finally 删除 busy 标记后，`renderSaveStatus()` 发现 `page.saveMsg` 为空，立即将提示清空。

线上复现：小 BMP 转换完成后，使 picker 抛 `AbortError`，得到 `saveStatus=''`，且错误区隐藏；使 picker 抛 `NotAllowedError`，保存处仍为空，只在全局错误区保留原始错误。

影响：用户取消对话框后看不到“尚未保存、结果仍在、可重试”的状态；磁盘/权限故障的本地反馈也消失。

建议：取消和失败也设置持久的 `page.saveMsg`，保留可重试说明；验证失败/取消后再次保存成功。任务列表的独立保存入口也检查同样的提示合同。

### R4 · P2：缺少本地保存能力时，警告隐藏到转换完成之后

位置：`static/tools/tools-slides.js:1407`、`:1753`；`templates/tools_slides.html:244` 的初始隐藏结果区。

初始化会调用 `renderSaveStatus()`，但提示位于隐藏的结果区。模拟缺少 `showSaveFilePicker` 的环境，首次选择文件前警告不可见，仍能执行完整复制和转换；完成后才出现禁用的保存按钮和不支持说明。

影响：以“本地转换并保存”为目的的用户可能处理大文件后才知道无法取出产物。该测试是 Chrome 中能力禁用的复现，未冒充 Safari/Firefox/手机实机测试。

建议：文件选择之前显示能力检查；明确本地导出不可用时的选择。若上传路径仍可工作，可保留并明确展示该路径，不应笼统关闭所有功能。不要默认整文件 Blob 下载作为大切片导出的兜底。

### R5 · P3：不支持格式的报错仍列旧格式集，与真实能力冲突

位置：`static/i18n.js:1555`、`:3198`。

错误说明只列 KFB/KFBF/Aperio SVS-JPEG/MRXS，但真实页面与已验证实现还包含 BMP/JPEG、SCN、NDPI、通用 TIFF、VMS、BIF 等有限变体。线上选 PNG 会出现这段旧说明；本轮 BMP/JPEG 转换成功。

建议：短错误说明指向一份统一的支持格式/限制说明；避免继续复制多份容易过时的列表。PNG 本次被拒绝本身符合当前支持范围，不是解码 bug。

### R6 · P3：普通 BMP/JPEG 结果显示“MRXS 拼接重编码”

位置：`static/tools/tools-slides.js:1356`，`static/i18n.js:1484`、`:3127`。

结果只要带 `composed` 字段，就使用 MRXS 专用标题；普通 BMP 转换截图也显示该标题。数据可以是真实重编码统计，但格式名称不正确。

建议：使用中性标题“瓦片重编码摘要”，或按真实输入格式显示标题。

### 当前不能确认的结论

- 转换工具页未统计、浏览器本地转换没有完成事件；页面也承诺除静态代码外不主动外连。因此无法回答历史真实转换人数/次数。
- `conversion_jobs` 为 0 是服务器转换任务为零，不能证明 WASM 本地转换没人用。
- 已上传的 TIFF/SVS 没有可信的工具来源标签，既可能原始上传，也可能转换后的产物；不能擅自归为转化成功。

若要观察结果：先补工具/指南访问覆盖及去重修复；再设计知情且可关闭的匿名结果统计，仅采用固定格式类别、成功/失败阶段、错误码和粗粒度耗时等允许字段。需同步更新现有“本地阶段零额外网络”的说明，不传文件名、图像、文件哈希或私有资源标识。上传来源另加明确但不能用于权限判定的来源字段。历史数据保持“未知”，不猜测回填。
