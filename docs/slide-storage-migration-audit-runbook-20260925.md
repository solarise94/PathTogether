# 历史文件管理迁移：上线前审计与切换手册

日期：2026-09-25。配套[实施任务书](slide-id-storage-refactor-agent-plan-20260925.md)。

**本文件规定实施 Agent 需要开发、演练和交付的迁移程序；当前尚未执行生产数据审计或迁移。以下脚本名及参数是待实现接口，不是已存在的可运行命令。** 新系统开放前，必须先证明旧资产的身份、字节、授权和容量责任能够正确迁移。审计不通过不能用强制 owner 转移或按同名自动认领来绕过。

## 1. 终态与执行边界

- 正常服务的历史资产保留原 slide_id，迁入独占 ID 包；新旧资产共用 resolver、授权、发布状态、删除和计费实现。
- 旧文件名只作为冻结 URL 别名和展示快照；改显示名、删除重传都不能重绑旧别名。
- 歧义记录进入隔离清单，不暴露内容、不丢弃证据。隔离不是成功迁移，数量与处理责任必须单独披露。
- 正常运行时退役 legacy 文件扫描、按名字隐式建行、按名字管理权限和旧布局读取。受限迁移工具可以读取备份中的旧布局。
- 本次文档不触发生产变更。实施先完成工具与副本演练，再提交具体窗口、迁移清单、备份和回滚方案；生产切换按届时用户授权执行。

## 2. 上线前只读审计

### 2.1 先确定真实数据边界

记录应用/worker/sidecar 的提交与镜像摘要、schema 版本、数据库实例、UPLOAD_DIR 实际挂载、宿主与容器路径映射、文件系统和可用容量。只记录配置键及非秘密定位信息，不把 SMTP、数据库密码、COS 密钥或分享 token 放进报告。

盘点所有 writer：V1/V2/COS、转换、百度导入、CLI 导入、管理修复、清理/reaper、定时任务、直接访问宿主目录的脚本。核查关联缓存、associated 文件、转换源、备份和导出目录；明确哪些是资产内容、可重建缓存、外部引用或独立导出，不默认全盘都属于上传资产。

审计工具用只读 DB 会话与只读源挂载；输出单独放权限受限目录。不得 import 会启动 worker、建表或自动修复的应用入口。扫描不跟随符号链接，不试图打开设备/FIFO，不执行自动清理。

### 2.2 双阶段审计

1. **在线预审**：分批导出元数据、关系和任务；限速扫描路径、文件类型、大小、mtime、dev/ino/nlink、伴侣文件及容量。记录扫描起止时间，明确这是非一致性快照，不据此直接授权搬迁。优先发现归属歧义、漏账、缺文件和空间不足。
2. **停写最终审计**：停下所有 writer，排空/处置在途任务；对 DB 和文件集建立同一停写边界的备份/快照，并验证可恢复。以冻结数据生成最终 manifest，逐文件校验哈希和包结构。全量哈希安排在副本或受控窗口，避免在线扫描耗尽生产 IO。

无法保证停写边界时，不得把分别取得的 DB dump 和文件复制当作一致备份。迁移应用前重验源 manifest；源身份、尺寸或内容变化就中止该项并重新审计。线上预审不能替代最终停写审计。

### 2.3 必查项目

| 对象 | 需要核实的证据 | 异常裁决 |
|---|---|---|
| slide 身份 | ID 唯一、旧名映射、owner 存在、名称历史、来源任务/导入记录 | owner 空、失效用户、名称复用或归属冲突列入人工核对，不回落认领为平台 owner |
| 文件/包 | 文件与元数据双向对应；逻辑入口、伴侣路径、全包大小、文件哈希、格式试开 | 缺失/破损/目录逃逸不可标 ready；未知归属文件只隔离 |
| 外部可写性 | symlink、跨根路径、hardlink 多路径、外部 writer | 不跟随未知链接；受支持源必须复制为隔离受管字节，无法确定依赖则阻塞该项 |
| 授权 | owner/public、shares 成员、claimed grants、view grants、Demo、run/session 范围 | 列出迁移前后授权差异；无法证明引用属于当前内容时禁止继承 |
| 业务引用 | 项目、ROI、评论、变更流、研究记录、AI 回放/缓存引用 | 活动关联不能悬空或指向新同名资产；历史记录保留原文并附解析状态 |
| 任务 | 上传/转换/导入/COS 状态、intent、lease、generation、staging 和远端资源 | 排空或明确取消并完成清理；不让旧 worker 猜测接管新布局 |
| 容量 | 每 owner 的 retained/ready/staging 字节、used/reserved、删除待清理 | 每份存活字节有责任项；差异单独核准，不静默归零 |
| 派生数据 | associated、缩略图、tile cache、转换源和导出物 | 按保留/重建/独立对象分类，不能漏迁必要内容或混入重复结算 |

**同路径、同文件名、同 SHA 都不能证明历史所有权。** 对已知有同名覆盖风险的记录，需要来源任务、历史审计或经确认的归属证据；没有证据就明确 unresolved，而不是伪造“已验证”。普通元数据一致性结果应标明证据强度与已知限制。

## 3. Agent 应实现的工具和输出

工具应复用统一存储/关系模块，禁止每个脚本再实现一套路径及 owner 推断。接口建议如下，可调整命名但不能缺失职责：

| 工具 | 默认行为及必要约束 |
|---|---|
| `scripts/audit_slide_identity.py` | 只读 inventory + relationship + quota 审计；支持在线浅审与冻结全审，分页/限速、明确 incomplete 标记 |
| `scripts/plan_slide_migration.py` | 根据冻结审计生成确定性计划；无生产副作用，不随机重新分配已有 ID |
| `scripts/migrate_slide_storage.py` | 默认 dry-run；apply 必须给 plan ID/校验摘要、目标环境及停写证明；持久 checkpoint，可重跑，不删源 |
| `scripts/verify_slide_migration.py` | 独立重新读取实际 DB/磁盘核验，不能仅相信迁移日志的 success 字段；失败返回非零 |

输出文件至少包含：

- `inventory.jsonl`：逐资产/孤儿项事实、扫描版本和证据引用。
- `issues.jsonl`：稳定问题 ID、类型、严重程度、关联资产、处置状态、责任人/证据；不得把 ignored 当 resolved。
- `migration-plan.jsonl`：逐项操作和预计成本。
- `migration-journal.jsonl` 或持久 journal 表：plan ID、item ID、阶段、输入摘要、结果/错误；数据库进度必须与实际提交一致。
- `verification.json`：独立核验结果、未验证项、授权差异、容量差异、测试与恢复演练证据。
- `summary.md`：供人审核的脱敏计数、风险、空间/耗时估计与 go/no-go 裁决。

逐项计划至少记录：保留的 slide_id、冻结旧 alias、owner 及证据来源、源相对路径/包 manifest/哈希/大小、目标相对路径、格式、依赖关系及授权映射摘要、旧/新容量责任、动作（migrate/quarantine/retain-history）、回滚定位。计划整体带版本、环境标识和摘要，避免拿测试计划执行到生产。分享 token 等秘密用受限内部映射或不可逆标识，不复制到公开 evidence。

报告必须分开列出：逻辑资产数、物理文件数、总逻辑字节、inode 去重物理量、账本量、额外迁移/备份空间。不能把 hardlink 去重后的磁盘数字直接当用户配额。工具必须对扫描错误、无权限、读取变化、遗漏分页返回 incomplete/失败，不能报告全量通过。

## 4. 迁移算法与崩溃恢复

每项使用持久状态：`planned → copied → verified → bound → postverified`；异常保留失败阶段和重试原因。资产正常状态仍使用主方案的状态机，不引入另一套公开可见性规则。

1. 核实 plan 摘要、源冻结状态、目标磁盘水位、ID/owner/既有映射未改变。旧 owner 不因搬迁而变更。
2. 在目标卷私有 staging 构建完整包，复制原内容；保留多文件包内部关系。默认复制隔离，禁止与外部可写源共享 inode。空间不足应阻塞或重新制定批次方案，不降级为无备份删源。
3. 全包校验大小和文件 SHA；验证真实格式、关联资源及代表性 tile，fsync 必要文件/目录，no-clobber 发布到 ID 目录。已存在目标仅在 journal 与完整 manifest 都证明是同一迁移项时复用，否则报冲突；不依内容相同认领。
4. 在短事务中 CAS 绑定存储位置/布局，完成已审核的 ID 关系回填、状态和配额校准；与新 writer 使用相同资产锁合同。不得对同一个历史资产再次收取上传配额。授权变更只能来自已审核计划，不能因文件搬迁新增权限。
5. 独立核验实际绑定与全部引用，才标 postverified。恢复时从 DB、journal 和 manifest 共同判断，不以单个文件存在为成功依据。

旧源保留只读并列入迁移备份容量，不再被业务 resolver 服务；不得当作第二份可见资产。保留期、负责清理者、清理前验证条件写入具体上线计划。备份容量与用户资产配额分列，不能无账消失，也不能重复向用户收取。清理需专门的可审查 manifest，不能对旧根目录直接递归删除。

## 5. 上线顺序及硬门禁

顺序：在线预审 → 解决问题/形成隔离决议 → 副本演练及恢复演练 → 具体上线方案 → 停写与一致备份 → 最终审计及计划冻结 → 兼容维护版本和增量 schema → 应用迁移 → 独立复核 → 最终运行版本 → 开放读写。

停写要同时控制用户 API 和所有后台 writer；迁移期间不对外运行可能绕过状态门禁的旧镜像。读取缓存/sidecar 需在切换时重建或失效。多个版本协作的顺序必须在部署包中具体写到镜像摘要，不以“滚动更新即可”代替合同。

以下全部满足才能开放服务：

1. 全部拟开放资产保留原 ID、有明确 owner、处于 ready/id_bundle，逐文件 hash/尺寸和逻辑包完整性一致。无法满足者必须经明确决议隔离，报告准确披露；不能无声漏迁。
2. 每个旧授权、项目、标注及活动引用有唯一合法映射或明确的拒绝/隔离结果；无意外新增可见性。授权差异报告同时包含意外缩小权限，不能只测越权。
3. 旧分享 token、已领取分享、显式授权、Demo、插件和 AI 各至少有正负访问验证；旧名重传场景不继承旧权限。
4. 每 owner 的 used/reserved 与 retained/staging/待清理实际责任对齐；COS 远端容量单独核算，不与本地搬迁混算。
5. 活跃旧任务已排空，或取消与远端/本地清理均有闭环；无仍可写旧根路径的进程和计划任务。
6. 中断后重跑不会重复资产/关联/计费；恢复演练确实恢复对应 DB 和文件数据，而非只证明备份命令成功。
7. 所有新读写走 ID；旧物理布局读取从正常运行链路移除，保留别名仅用于固定 ID 查找。管理后台、CLI、HistoPilot 均验证，不只验证 Web 上传。
8. 审计无 incomplete 项；阻断项为零，隔离例外逐项有决议。实际支持格式完成代表性试开，迁移总数/字节与逐项日志能互相核对。

迁移通过不等于 COS 可以开启：CSP/三 origin、桶生命周期和 Phase 5 仍按原独立门禁执行，capability 保持 off。

## 6. 回滚与旧代码退役

- 新写入未开放前，允许在维护状态按 journal 恢复匹配的旧存储映射和关系；只能切到保留状态/授权防护的兼容版本。不可把有歧义资产恢复成旧系统默认可见。
- 新 ID 写入开放后，只能回滚到仍理解新 ID/schema/布局的版本，或停写前滚修复；不能为了回滚把新文件改成原始名称。
- 对恢复点之后的新写入制定保全方案，不直接覆盖整个生产 DB 为旧 dump。验证失败时继续维护状态，保留证据和原始字节。
- 最终交付逐项“已删/过渡/保留”清单：force-owner、同名冲突/认领、按名字元数据建行、重复 promote/结算、目录扫描公开、legacy 布局分支、双名称写入全部有退出结论。
- 旧列/JSON/接口在调用者迁完且审计通过后独立做 contract migration；不可提前 drop 数据破坏回滚。冻结 alias 若用于长期书签兼容可保留薄查询层，但不能保留文件名授权或存储旁路。

## 7. 本次与后续交付状态

本次交付的是代码审查后的设计和执行合同。后续 Agent 必须分别报告“工具已实现”“副本演练完成”“生产预审完成”“生产迁移完成”“旧副本清理完成”，附环境与时间；不能把前一项当后一项。上线前向用户展示审计摘要、隔离清单、剩余风险和具体切换/恢复方案。
