# ux-formats Linux / Docker 内存核验

日期：2026-10-05（Asia/Shanghai）。应用候选：`d861dd1`。

用户接受本机 Docker/Linux 作为本轮低内存核验方式，并明确没有 Windows 设备，本轮不测 Windows。本报告不宣称真实低配硬件或 Windows 验收。

## 环境

本机 Docker 29.1.3、cgroup v2；容器限制 4 GiB RAM、禁用 swap、4 CPU，网络关闭。使用已有 Alpine 镜像作容器载体，只读挂载本机 Linux 库、Node、Chromium、候选代码和测试输入，仅测试 scratch 可写。浏览器及原生参考转换均在容器内执行。它是转换器内存测试环境，不是平台发布镜像的另一次打包测试。

KFB 使用 saver profile，覆盖复制进 OPFS、hash、探测、转换、结构/摘要校验。RSS 为浏览器进程树 RSS 求和，与既有测量口径一致；不等于容器独占物理内存。测试没有访问生产。

## 结果

| 场景 | 浏览器 RSS 峰值 | 相对空页均值增量 | 结果 |
| --- | ---: | ---: | --- |
| 合成 KFB 0.98 GiB，保留画质 | 566 MiB | 117 MiB | 完成，原生逐字节一致 |
| 合成 KFB 9.79 GiB，保留画质 | 615 MiB | 166 MiB | 完成，BigTIFF/SubIFD/tile 边界及流式摘要校验通过；本次未重做该大文件原生对照 |
| 合成 KFB 0.98 GiB，有损模式 | 568 MiB | 119 MiB | 完成，原生逐字节一致 |
| 公开小型 JPEG SVS，保留/有损 × OME/经典 | 未单独测进程树峰值 | — | 4/4 与原生逐字节一致 |
| 公开小型 MRXS 完整包，保留/有损 × OME/经典 | 未单独测进程树峰值 | — | 4/4 与原生逐字节一致 |

- 9.79 GiB 输入为 10,512,547,212 B，输出 10,509,701,545 B；转换约 42.8 秒，全流程约 124.9 秒。输出 sha256 `c0cef73909205b161e87c62bcfd7cdf8ee0bce5b561ee13bcc08711898d4280a`。
- 有损 KFB 转换约 57.5 秒；输出约 539 MiB。这是合成纹理压缩率，不能替代真实组织样本的大小或画质结论。
- 四个容器均 exit 0，Docker `OOMKilled=false`。SVS/MRXS 套件和 KFB 有损的终态 cgroup `oom=0, oom_kill=0`。两个保留画质容器没有终态 memory.events 采集器；9.79 GiB 运行中采集为零，不能冒充终态计数。
- cgroup 总峰值包含文件缓存：大 KFB 运行中达到 4 GiB 并发生缓存回收；这不是浏览器 RSS 达到 4 GiB，也不是 OOM。格式小样本套件总峰值约 741 MiB；KFB 有损整容器峰值约 3.27 GiB（含文件缓存及原生参考转换）。
- 各 KFB 浏览器内存增量均低于 512 MiB。0.98→9.79 GiB 的增量峰值约 117→166 MiB（约 +42%），不将旧计划的“增长≤20%”指标标为通过。

## 范围与测试处理

9.79 GiB 首次启动被浏览器磁盘容量估算预检拒绝，harness 允许跳过不确定空间预检后重试成功。真实 OPFS 配额仍由浏览器执行；这里没有验证用户确认对话框。未上传超平台上限的结果。

有损内存测试采用私有 driver 副本，将原生参考缓存名按编码模式区分，防止复用保留画质的参考文件。没有修改应用代码或正式测试文件。JSON 中的完成状态和 parity 均单独断言，不仅依赖 driver 的退出码。

原始证据：本 worktree `.gate-tmp/docker-memory-20261005/`，包含容器状态、cgroup 记录、浏览器内存 JSON、格式 parity JSON 及运行脚本。四个测试容器和大型测试浏览器 profile、生成的临时输入链接/参考产物已清理；原始共享样本保留。
