# HistoPilot User Feedback Review

## Executive Summary｜结论与决策

- **先修“选区控制”和“结果交付”，再优化判读表达。** 这位用户希望 AI 回答“我正在看的这一块是什么、为什么、接下来怎么看”。生产记录显示，普通“当前视野”指令没有绑定浏览器视野；显式坐标指令能影响导航，但没有把分析严格限制在矩形内。
- **“没有总结”存在可复现的前端缺陷。** 本次查到的 7 个会话中，服务端产生了 8 次非空完成总结；线上同版本代码会把已有引导句误当成完整总结而跳过展示，历史回放也忽略 `finish.summary`。应优先修复，不能简单归因于模型不输出。
- **“太保守”包含信息不足和表达不够聚焦两部分。** 用户使用的 6 个不同切片文件中，5 个是单层 JPG/JPEG、MPP 未知；系统仍混用覆盖范围与倍率提示。应明确图像证据上限，输出首要判断、支持/反对证据和最小补充信息；不应因为用户给出“癌症转移”背景，就把全部疑似区域直接定为癌。
- **推荐顺序：总结与恢复可靠性 → 显式范围约束 → 证据化回答。** 下文区分生产事实、代码复现和待验证事项；分析阶段只输出文档，未修改业务代码或部署。同日的修复轮次与验收结果见 §7。

## 2. 问题一：坐标能被理解，但选区没有成为执行边界

### 2.1 普通发送没有自动绑定“当前视野”

普通发送请求携带切片、文本、会话和请求标识；公共发送函数补充通道渲染上下文，但未补充浏览器当前视野或矩形选区。界面的“引用选区”按钮才调用 `selection.getBbox`，把坐标拼成“重点看 level-0 区域…”的文字。这里的 `captureAiSelection` 管理的是会话选择世代，并非病理 ROI。

因此，“分析当前视野”对用户意味着浏览器里的画面，对 AI 却可能意味着它上一次取到的快照。S3 的后续完成总结把“当前视野”解释为上次标注 3 附近，并进一步复核了三处已有标注；日志中没有浏览器视野快照，不能证明它与用户当时看到的范围一致。

系统主提示又要求先看全片概览，再主动寻找可疑灶；局部问题与全片巡检的默认策略存在张力。已确认的是上下文合同缺失，不能仅凭截图认定用户忘记了某项设置。

代码证据：`main.js` 第 207、255、791、1447 行；`server.ts:342`；`prompts.ts:36`。

### 2.2 用户已经尝试了坐标入口，不能再归因于“不会使用”

S4 消息 15 明确发送：

> 重点看 level-0 区域 (x=31438,y=35499,w=3592,h=3111)：

随后工具记录如下：

| 步骤 | 真实记录 | 可以确认什么 |
|---|---|---|
| 首次导航 | 中心 `(33200,37000)`，level 2 | 中心在用户 ROI 内，AI 没有完全忽略坐标 |
| 对应快照 | `(31152,34952,4096,4096)` | 覆盖整个 ROI，但快照约 33.4% 面积在 ROI 外 |
| 高倍导航 | 中心 `(34800,36200)`，level 0 | 中心仍在 ROI 内 |
| 对应快照 | `(34288,35688,1024,1024)` | 右缘超出 ROI；约 27.5% 面积在 ROI 外 |

越界面积按矩形相交计算，分母为相应快照面积；不是“模型注意力偏移率”或错误诊断率。看邻近组织可能有上下文价值，但产品目前没有向用户区分“仅框内分析”与“允许参考框外”。工具中的切片/快照边界校验不等于用户 ROI 边界校验。

**判断：显式坐标被执行，严格范围约束未建立。** 这比“模型完全不听话”更接近实际，也说明单纯强化提示词不足以保证行为。

### 2.3 停止后恢复错误进一步破坏了操作连续性

S4 在 17:16:07、17:18:45 有暂停事件；17:20:44 和 17:20:50 出现同一错误：`Cannot continue from message role: assistant`。这是同一会话的两条错误事件，不是两个失败用户。

本地 runner 调用 `agent.continue()`；所安装的 agent 库在消息末尾为 assistant 且没有可用续接消息时会拒绝继续。该错误与日志末尾状态相符，具体如何在取消、保存和再次继续之间形成，需要补充后端回放测试才能认定完整根因。不能把失败归为网络波动，也不应要求用户每次重建会话绕过。

证据：S4 消息 15–34 和终态事件；`tools.ts:1251`；`agent-runner.ts:2868`。

## 3. 问题二：“太保守”和“没有总结”需要分开解决

### 3.1 总结已经生成，交付链路会漏显

在 6 个最终状态为 finished 的会话中，共有 **8 个非空 `agent_finished.summary`**，与 8 次 `finish` 调用对应。S4 未完成，没有总结符合其中断状态。所有会话顶层 `summary` 字段均为空，但消息中的 `finish.arguments.summary` 和事件仍保留正文，故不能凭顶层空值判断模型没写。

发现两条独立缺陷：

1. **实时显示误去重。** `agent_finished` 只要发现已有非空流式气泡，就跳过终态总结，未判断那个气泡是否真的包含总结。S3 首次完成、S5、S6 的 `finish` 同条 assistant 消息中，正文只是“下面给出总结”一类引导句，真正总结只在工具参数里。已有前文气泡也可能触发此分支，不能把影响范围机械限定为这三次。
2. **历史回放丢失。** `renderAiTranscript` 遇到 `finish` 不渲染参数中的总结，注释假设总结已在正文或状态行；`finish` 的工具返回正文又只有“已结束”。因此刷新、重开或重建轨迹后，仅存在于工具参数的总结不能可靠恢复。

已核对线上 `main.js`、`renderer.js` 的 SHA-256 与本地文件一致，并加载真实前端代码做了 **2 个最小复现**：分别复现“引导句存在时跳过总结”和“finish-only 回放缺少总结”。测试通过表示缺陷成功复现，**不表示已修复**。测试使用最小 DOM 环境，不是该用户浏览器的录像，无法证明每次总结实际曝光情况。

代码证据：`main.js:1282`；`renderer.js:1476`；`tools.ts:2117`；`transcript.ts:125`。复现材料保存在本次分析附件目录。

### 3.2 用户需要更明确的解释，不是更武断的标签

截图中的诉求包含三层：是否存在肿瘤的直接回答、疑似区域的可理解解释、给定临床背景后能否聚焦判读。生产记录也出现“是否有肿瘤组织”和“间隙的是什么细胞”的具体问题。

当前回答往往列出多个鉴别方向，再建议进一步确认；对这类用户，缺少“优先考虑什么、哪条证据最关键、为什么还不能排除另一种解释”的排序，会被感知为模糊。与此同时，S3 总结也出现“全片未见……”这样的广泛表述，而采样导航不等于完整覆盖；产品问题并非单向“太保守”，还包括结论范围与证据覆盖不匹配。

**建议回答结构：一句直接答复 → 已观察到的证据 → 首要解释及替代解释 → 不能判断的具体原因 → 一项最有价值的下一步。** 不输出没有校准依据的百分比置信度，也不通过统一提高“判癌倾向”解决满意度问题。

本次没有切片专家金标准，未评估病理结论的准确性；这里评价的是回答结构、证据绑定和任务完成度。

### 3.3 图像条件和倍率提示让“信息不足”更难被解释清楚

5 个 JPG/JPEG 文件的首条上下文均为 1900×1900 像素、金字塔仅 1 层、MPP 未知；只有 SVS 文件提供完整金字塔和已知 MPP。文件名中的“×”和模型从图上估算的倍率不应自动当作可信元数据。

另外，每个会话都调用了一次 `dev_sample_tma__slide_summary`，7 次均返回降级占位、尺寸与 MPP 为空。主上下文部分信息其实已存在，但重复调用的空结果增加了冲突和无效步骤。

工具提示还把“覆盖比例很小”称为“高倍”。例如 S4 的 level 2 已明确约为 9×，快照返回却附“高倍…不必再放大”；单层图像也会收到继续降层放大的提示。这是提示口径不一致的真实证据，不能据此断言它已经造成误诊。

**应把“取景范围”与“真实细节能力”分开表达。** 已知 MPP 时依据规范化元数据；未知时显示“原图最高分辨率，光学倍率未校准”，说明当前缺少的细节，并允许补充对应高分辨率区域。没有可用回调的样例工具不应继续进入生产读片工具集。

证据：S1–S7 首条上下文与样例工具返回；S4 消息 23；`tools.ts:1120`。

## 4. 优化方案：范围可控、证据可懂、结果可恢复

### 4.1 将选区变成一次运行的明确合同

- 输入框旁明确提供“当前视野 / 选中区域 / 全片巡检”。存在活动选区时推荐选中区域，显示范围缩略图、标注编号和“仅框内”状态；用户仍可主动切换全片。
- 发送时冻结 切片及版本、范围类型、原图坐标、选区及版本、通道渲染上下文。浏览器坐标、旋转/镜像与原图坐标统一转换；提交后的新选框不能悄悄改变正在执行的任务。
- 范围在前端、平台代理、sidecar、快照、落标与恢复链路中保持一致。仅检查导航中心不够，要验证最终取景和标注范围；ROI 太小或形状不支持时明确提示，不静默回退全片。
- 默认仅框内分析。若确需周围组织作参照，先说明原因并提供“允许扩展”操作；结果区分别标明 ROI 内证据和框外参考，不把框外结论算成框内发现。
- 多个可选对象同时存在时显示将使用哪一个。当前代码优先返回临时 ROI，再考虑选中矩形标注，需避免旧 ROI 抢占用户刚选中的标注。

### 4.2 单独保存并渲染每轮最终答复

- 总结成为带 `run_id/answer_id` 的独立结果对象，与运行状态分开；完成时持久化，断线重连、刷新和历史回放使用同一结果来源。
- 用结果标识做幂等去重，不能用“已有文字气泡”判断总结是否展示。保留前面的解释文字，同时显示真正的最终答复。
- 兼容历史会话：优先从已保存最终结果恢复；没有时解析成功 `finish` 的参数；再处理纯文本结束的回合。不要要求模型再次读片才能看到已生成的总结。
- 完成卡固定展示“范围、直接回答、关键证据、限制、下一步”。错误或暂停展示“部分完成”和已保留内容，不只显示“本次读片已完成”。

### 4.3 提供证据化判断和上下文入口

- 将“已知背景”和“本轮问题”分开录入；标识背景是用户提供、报告已证实，还是待验证假设。后续修改保留版本，避免旧背景沿用到别的切片。
- 对“这是癌症皮肤转移患者”的输入，可以调整关注点和解释顺序；仍需区分背景事实、框内可见证据与区域结论。可提供“寻找与该背景一致的可疑区域，待复核”，不能把背景当作所有区域的标签。
- 每条解释关联对应 ROI/快照，点击证据即可回到该处。界面区分用户目标、AI 当前取景、待复核发现，不能只靠黄框、绿框等颜色传递含义。
- 面向不熟悉形态学的用户，先用一句通俗解释，再展开专业描述。无法判断时讲清“缺哪种证据”，避免重复空泛的“请结合临床”。

## 5. 排期与验收：先恢复可信交付，再提升判读体验

以下是相对优先级，不是已承诺工期。责任角色由团队落实。

| 优先级 | 工作项与建议责任方 | 完成标准 |
|---|---|---|
| P0 | 总结实时显示、持久化与回放；前端＋会话后端 | 纯 finish、文字引导＋finish、纯文本结束均有最终答复；刷新、重连、切换会话后仍存在且不重复 |
| P0 | 停止后恢复状态机；agent 后端 | 在文本、工具调用、工具执行和快照消化阶段停止后均能合法继续；不重复落标、不重复计费，不再出现 assistant 尾消息续接异常 |
| P1 | 当前视野和 ROI 全链路合同；查看器＋平台＋sidecar | 普通发送能准确绑定所选范围；矩形、边界、旋转/镜像、旧 ROI、新选标注、会话续接和请求重试均有回归用例 |
| P1 | 倍率与图像质量提示、剔除不可用样例工具；图像服务＋agent | 单层未知 MPP 不再收到不可执行的降层建议；覆盖比例不再冒充倍率；无效样例工具不进入候选集 |
| P1 | 最终答复模板与临床背景入口；产品＋模型评测 | 对直接问题先作明确答复；证据、限制和上下文来源可见；不把假设或背景自动升级为结论 |
| P2 | 证据回跳、标注语义与行为观测；前端＋数据 | 用户能区分“我选的”“AI看的”“AI标的”，并回到支持结论的图像位置 |

**上线验收分两类。** 工程验收以确定性回放为主；判读表达验收使用由病理专业人员审阅的样本，混合明确阳性、明确阴性、证据不足及不同输入图像质量，分别评价回答针对性、证据支持和不当过度断言。不能把“更敢下结论”当成唯一提升指标。

建议在修复前建立基线，再观察以下指标，当前日志不足以给出可靠线上数值：

- **范围遵从率：** 有效“仅框内”运行中，所有分析图像/标注符合目标约束的比例；允许扩展的运行单列。另记系统拦截的越界尝试，不能与实际越界混算。
- **总结交付率：** 服务端已有最终结果、且前端收到终态的运行中，最终答复成功渲染的比例。区分 DOM 渲染、进入可视区域和用户阅读，不混为“看过”。
- **总结恢复率：** 有最终结果的历史会话打开后，能正确恢复该轮答复的比例。
- **纠偏与恢复：** 按 run 统计重复范围指令、停止后继续成功率、重复落标/计费；用户停止可能有正常原因，应结合上下文解释。
- **回答可用性：** 专家评审的针对性与证据支持评分，加用户“是否回答了我的问题”的反馈；与过度断言率共同评估。

最小新增记录建议包括：提交范围及来源、服务端接受范围、每张快照实际 bbox、是否允许扩展、终态原因、最终答复标识与渲染确认。以稳定 ID 关联，避免在行为埋点中重复保存完整病理内容。
