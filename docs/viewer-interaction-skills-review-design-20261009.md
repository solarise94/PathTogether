## 3. AI 标题整栏拖动

### 3.1 用户看到的行为

```text
┌──────────────────────────────────────────────┐
│ ✦  当前对话标题 ⌄          新对话   ⋯   ×    │  整条可以起拖
├──────────────────────────────────────────────┤
│ 对话内容                                     │
```

- 桌面端整条 header 可作为起拖区，包括标题文字、下拉箭头和右侧三个按钮。
- 不移动的点击保持原功能：标题打开会话列表；三个按钮分别新建、选项、关闭。
- 从按钮起拖并完成移动，**不执行按钮动作**。尤其不能移动完突然关闭面板或新建会话。
- 常态为 grab，拖动为 grabbing；按钮悬停仍可显示其 tooltip。标题截断不影响拖动。
- 不再把“双击标题重置位置”混在会话标题操作里。改放到现有 ⋯ →「重置面板位置」。
- 小屏（现有 ≤768px 分界）保持固定面板，不把触摸滚动变成拖窗；桌面触控笔按同一手势判定。
- 新对话在没有切片时仍禁用，不能为了让禁用按钮区域可拖而恢复它的业务点击。
  可用不带业务动作的父级区域处理该处拖动，保持 aria-disabled 与视觉反馈。

### 3.2 实现约束

1. `pointerdown` 只记候选手势和实际面板相对 viewer-wrap 的位置；不立即 preventDefault，
   不抢走按钮焦点，不写 localStorage。
2. 位移达到约 6 CSS px 才进入拖动态。达到阈值再捕获 pointer、关闭标题弹层，抑制本次 click。
   阈值以下正常点击；Enter/Space 键激活不走拖动逻辑。
3. 抑制范围绑定本次 pointer 手势，仅影响其生成的 click；不要用全局“接下来 500ms 不许点击”。
   覆盖 button 起手、拖出 header 后松手及 capture 重定向的事件目标。
4. 移动以 requestAnimationFrame 合并，优先 transform 合成；结束再提交 left/top 和一次位置持久化。
   不在每个 pointermove 读 frame 几何、写布局、再读布局。resize 继续独立处理。
5. pointercancel/Esc/失焦取消本次拖动并恢复起点；pointerup 完成；所有退出路径释放捕获、光标、临时样式。
6. 保留按用户记忆、窗口边界钳制、移动端切回桌面恢复；真实位置应从 DOM 读一次，
   不凭默认 right/top 常量推算首次起拖点。

## 4. 翻牌消除黑闪：连续图像交接

### 4.1 目标与视觉节奏

保留当前请求与动画并行。不能退回“先加载完再播放”，也不能通过增加动画时间掩盖问题。

```text
点击切片 ─┬─ info → DZI/render plan → 瓦片加载、绘制
          └─ 抽出/翻面 620ms → 缩略图铺开 340ms → 预览 → 清晰图
```

- 开片前：已有切片继续可见；首次开片保留当前空态/底色。禁止瞬间插入覆盖整个主视窗的黑幕。
- 翻牌：旧背景保留，牌背保持原蓝色。可以渐隐旧背景，但组织区域不应经过纯深色中间帧。
- 铺开：新缩略图成为完整预览；从牌面到铺开的图像全程至少有一份已解码图像在正确位置。
- 网络慢：保持已铺开的预览；若需要提示，用轻量「正在加载清晰图像」，不加遮罩或阻止操作。
- 交接：目标图像区域有完整可见底图后才淡出飞牌层（约 160–200ms）。
  图像本来存在的深色留白可以保留；禁止把“全画面都不能有黑色”当验收标准。

### 4.2 推荐技术方案

1. 分离“背景连续性”和“飞牌装饰层”。移除不透明黑色 stage 的职责；需要遮住新 viewer 清屏时，
   保留上一张已解码预览作为背景桥接，不用纯色填充代替组织图像。
2. 捕获上一张图像应发生在 `clearBaseThumb/viewer.open` 清理之前；保存当时裁剪、缩放位置。
   优先复用已有预览 DOM 和缓存，**不在每次切片时同步调用 toDataURL/getImageData**，
   不复制整张 2×DPR 大画布造成新的掉帧，不在动画中重新抓图或发缩略图下载。
3. 新目标预览沿用当前可用缩略图；确保 decode 完成后再让前一图层退场。
   如果使用第二个 img 元素，不能以“src 已赋值”代替 complete/naturalWidth/decode 检查。
4. 到达终点后，把完整预览交给 viewer 的底图层保持。确保 OSD 透明区域下方是这张预览，
   再淡出飞牌副本；不能在图像从 front 移到 landing 的同一帧让两处都空。
5. 将“可交接”定义为：当前 selection generation 匹配、目标几何有效、
   **完整底图已解码并可见，或目标可见图像区域已被已绘制且完成必要混合的瓦片覆盖**。
   有完整底图就无需等所有高清瓦片；没有底图则不能只凭 `e.tiles.length>0` 判就绪。
6. opacity 动画只作用在需要退场的图层。避免 landing 和遮幕同步降低 alpha 后透出空画布。
   不改变 OSD 画质、分辨率和瓦片并发来解决视觉交接。
7. 到 8 秒仍加载中：退出飞牌装饰，但先把完整预览移交底图，并提供加载/重试状态。
   不得一次移除所有可见预览重新露出黑屏；info 失败要明确失败，不能把旧图标成新图。
8. A→B→C 快速切片、取消、resize、切换通道及权限失效都用当前 openSlideSeq/图像版本校验。
   迟到 B 不能揭开 C 的图层；临时查看到期必须同时清理保留的背景/预览，不能留下旧权限画面。

验收必须录制逐帧视频或浏览器 filmstrip：现有“最终 canvas 有像素”测试不能检测中间黑闪。
至少测 warm cache、冷缓存、info 延迟、首瓦片延迟、缩略图 decode 延迟、快速连续选片。
对已知明亮测试图的组织区域采样，检测突降到背景色；不要使用整帧平均亮度，避免把原始黑边误报。

## 5. 将 AI 描绘改为按需技能

### 5.1 产品交互

- 从界面移除「允许 AI 描绘」checkbox，包括更多选项内的入口。
- 输入 `@` 时出现轻量技能候选；本轮只需要「描绘」，说明「圈出指定组织区域，生成待复核标记」。
  输入 `@描绘` 可直接发送；选择候选可变成可删除的小标签，不增加一排永久工具栏。
- 输入「帮我把这个视野里的腺体圈出来」「圈出右上角可疑区域」也能调用同一技能，
  不要求用户先打开某个设置。发送前命中明确意图可显示小标签「描绘 · 本次」，可删除。
- 删除标签须记录本条消息的显式关闭意图，不能下一次解析又悄悄加回来。
- 指代含糊，例如有多个框时说「圈出这个」，只追问目标范围；明确请求不再额外问“是否允许描绘”。
- 执行时对话显示简短状态「正在描绘……」；完成显示「已生成 2 个待复核标记」与定位入口。
  技术调用详情继续折叠。用户在标记工具条里调整、接受或删除，不把大批标记管理塞回聊天标题。
- 普通问答、总结、解释已有圈线，不自动开描绘技能。历史会话中曾开过开关也不构成下一轮授权。

### 5.2 调用案例与范围

| 用户消息 | 技能与目标 | 结果 |
| --- | --- | --- |
| `@描绘 帮我圈出当前视野的腺体` | 描绘；发送时冻结的视野 | 生成 pending 多边形，回复可定位 |
| `帮我把选框里的坏死区域圈出来` | 描绘；当前选框几何快照 | 使用选框，不移动/覆盖这个原选框 |
| `帮我把 xxx 圈出来`，当前有一个选中标记 | 描绘；选中标记附近的范围，结合明确目标 | 创建新结果；编辑已有标记需要另有明确指令 |
| `圈出整张切片中的可疑区域` | 明确全片范围 | 沿现有 AI 观察/预算机制分步处理，不把单次视野结果声称为全片完成 |
| `不要圈出来，只解释` | 不调用 | 文字/观察结果 |
| `报告里写“帮我圈出来”是什么意思？` | 不调用 | 引用文本不作为执行意图 |
| `这个蓝框是谁画的？` | 不调用 | 查询/说明已有标记 |
| 上一轮描绘完成，下一轮 `总结一下` | 不调用 | 不继承描绘权限 |
| `@描绘` 无切片，或只读分享/只读 fork | 不获得写权限 | 提示打开切片或转到有编辑权限的工作台 |

默认范围顺序：用户明确范围 > 当前选框/明确选中对象 > 发送时的当前视野。
请求保存 `slide_id + asset_revision + 坐标范围 + 相关 annotation_id/revision`；
用户在执行中平移镜头，不应让模型结果落到另一个视野。跨切片的输入草稿不能携带旧几何继续发送。
请求全片时遵循既有运行时长、成本和数量限制，不为本功能顺便放开配额。

### 5.3 服务端契约（需要跨仓升级）

技能是 HistoPilot 的产品能力定义，不是让用户安装 Codex SKILL.md。可用一个小型能力定义文件
保存名称、描述、意图示例、工具列表和范围规则；不为一个技能引入技能市场、额外租约表或复杂调度层。

推荐请求形态（**提议的新增契约，不是现有可用 API**）：

```json
{
  "task": "帮我把选框里的腺体圈出来",
  "requested_skills": ["delineate"],
  "skill_intent": "explicit",
  "target": {
    "slide_id": "sld_example",
    "asset_revision": "opaque-existing-revision",
    "kind": "roi",
    "bbox": { "x": 100, "y": 200, "w": 800, "h": 600 }
  }
}
```

- 浏览器只表达本次意图。服务端解析当前用户消息/显式技能选择，验证权限与目标版本，
  得出 effective skills；不能把请求中的 `skill_intent` 当成可信权限凭证。
- 自然语言走一次轻量意图判定，明确否定/引用不触发。可复用现有模型路由步骤做结构化判定，
  但只能读本次真实用户指令和合法上下文；不让模型回复、组织图片中的文字、工具结果自行激活权限。
  不每敲一个字就发模型请求。模糊请求追问，明确请求直接执行。
- 复用 `run_grants`：增加本次 `allow_ai_drawing`（默认 false）或等价能力字段，并绑定现有
  grant/session/slide/user/expiry。按一次逻辑 run 发放，不写成长期 session 开关。
  如需要区分能力版本，使用明确协议版本；不新建另一个并行“描绘授权系统”。
- HP 工具装配依据该 run 的服务端有效能力，不再从历史 session.allow_ai_drawing 决定新 run。
  执行时复查 run 有效性；PT plugin v1 与 legacy internal polygon/freehand 写路径同样复查。
  internal token 不能成为绕过本次能力限制的后门。
- 沿用现有请求去重、run grant、快照 attestation、切片版本、归属、审核状态与数量限制。
  保留 normalized→level-0 转换、越界和自交校验，不让技能文本改写这些规则。
- 停止/取消、权限到期、run 终态后拒绝新的迟到写入；已完成的幂等重放仅返回既有结果。
  断线重连同一 run 可以恢复；“继续”若是新 run，只在明确继续上次描绘任务时重新校验并发能力，
  新的普通消息不继承。不要在 finally 中简单把 session 开关关掉，制造并发和重连竞态。
- 两端不支持新能力契约时，显示暂不可用；不能静默永久开启旧开关。
  旧 flags/generation 可保留历史和过渡兼容，不在本轮做破坏性删表。
- AI 矩形 create_annotation 与描绘 polygon 当前不是同一个开关。保持已有矩形行为；
  用户本次调用技能创建的结果应标注来源。若还要禁止所有普通 AI 自动落标，属于额外产品决定。

### 5.4 结果可用性先于入口上线

rect / arrow / freehand / **polygon** 均须完成：画布呈现、命中、定位、编辑、
元数据序列化、恢复、分享投影与权限过滤。polygon 不能伪装成 freehand 再保存，
否则会丢失简单多边形验证与来源语义。可以共用纯几何函数，但保留原类型。
AI 结果仍待复核；人工修改保留原始来源快照、记录修改历史，不抹掉 source=ai。

## 6. 选框与标记：统一操作模型

### 6.1 对象与视觉

| 对象 | 保存方式 | 初始状态 |
| --- | --- | --- |
| 临时选框 | 本地草稿；用户点击「保存为标记」才创建记录 | 新建后已选中，可移动缩放 |
| 人工保存标记 | 既有 annotation_id + revision | 普通可见；选中后可操作 |
| AI 描绘结果 | 已落库，review_status=pending | 显示待复核；修改不自动接受 |
| 无编辑权限的共享标记 | 只读 | 可选择、定位、查看允许的详情；无可拖手柄 |
| AI 视野/历史路径等临时叠加 | 原插件观察层 | 仍为只读视角提示，不伪装为已保存标记 |

选中用单一蓝色轮廓和清楚的控制点；去掉截图里叠在一起的粗蓝外框、黄内框和常驻黄角点。
作者放在轻量标签/详情里，未选中轮廓更轻。锁定显示小锁图标，只有真正可编辑时才显示调整柄。
**选中不再隐藏其他标记**；“只看这条”移入对象 ⋯，与普通选择分开。

就近出现的工具条：

```text
临时框：     [保存为标记] [锁定位置] [⋯]
已存标记：   [编辑备注]   [锁定位置] [⋯]
AI 待复核：  [接受]       [编辑备注] [锁定位置] [⋯]
锁定对象：   [编辑备注]   [解锁位置] [⋯]
```

工具条放在对象上方、靠近边角，出视窗则翻到内部或下方，避免遮挡主要组织。
常用按钮桌面至少 36–40px、触摸 44px；视觉柄可小，但命中范围桌面约 16px、触摸约 28px。
删除、复制、只看此标记、精确坐标、查看来源等收进 ⋯。未有业务支持的动作不要放空按钮。

### 6.2 手势优先级

| 当前命中 / 状态 | 单击 | 拖动 |
| --- | --- | --- |
| 空白图像 | 取消选择 | 平移切片 |
| 未选中的标记边线/内部 | 选择标记 | 未预先选中时仍平移切片，避免误移大框 |
| 已选中、未锁、可编辑的内部/边线 | 保持选择 | 移动整个对象 |
| 已选中对象控制点 | 保持选择 | 调整对应边/角/端点 |
| 已锁定或只读对象 | 选择并显示锁定/只读状态 | 平移切片，绝不偷偷移动对象 |
| 按住 Space（输入框外） | — | 无论经过哪个对象都平移切片 |
| 明确启用矩形/箭头/描图工具 | 按该工具规则 | 新建对象；不误进入旧对象编辑 |

手势优先级：UI 工具条 > Space 平移 > 显式绘制 > 可编辑选中对象的手柄/本体 > 普通选择/平移。
一次 pointer 会话只交给一个处理器。不要先移动切片，再发现命中标记把它拉回来。
优先在 viewer 容器捕获阶段命中测试：只在确认对象编辑后消费事件，其余交给 OSD，
不依赖全屏透明 canvas 永久拦截再手动模拟 OSD 的全部拖动行为。

- 首次点击选择，下一次按住即可移动，不必再去远处点“编辑”。可直接拖控制点调整。
- 矩形四角改双轴、四边改单轴；尺寸比锁保留在精确设置里，与「锁定位置」名称和状态区分。
- 箭头端点调整、线段整体移动；freehand/polygon 整体移动和包围框缩放。
  polygon 的「编辑轮廓点」放在 ⋯，进入后才展示顶点，支持拖顶点及增删顶点，完成时校验非自交。
- 边界约束和所有提交仍以 level-0 图像坐标为准；屏幕阈值、柄大小以 CSS px 为准。
  旋转/镜像时矩形应投影四个顶点，不能只拿两个对角点拼屏幕轴对齐框。
- 移动只预览，松手一次提交；没有有效位移不发 PATCH。拖动中不逐点发网络请求。
- 键盘：输入框外方向键移动 1 个 level-0 px，Shift+方向键 10px，重复按键合并提交/撤销单元。
  Esc 撤销本次未提交几何；Delete 对锁定对象不生效，对可删对象提供明确删除和撤销反馈。
  常用撤销继续用 Cmd/Ctrl+Z；文本编辑内保留浏览器本来的快捷键。

### 6.3 锁定语义与存储

名称统一「锁定位置 / 解锁位置」：冻结几何并防止意外删除；仍允许有权用户编辑备注、评论、
查看来源或定位。不是权限锁，也不把共享用户提升为可编辑者。

- 临时框：`draft.geometryLocked`，只对当前草稿有效；切片切换遵循现有草稿处理。
  保存成标记时带上该状态，不因为刷新画面意外解锁。
- 已存标记：建议在现有 `rois.data` 内加入 `geometry_locked: boolean`，缺省 false。
  利用现有 revision、history、change_seq，无需另建锁表、锁持有人或心跳租约。
- 任何本来有编辑权的人可以解锁；记录操作者和历史。owner 特权沿用现有规则，不把“能看切片”当编辑权。
- 主站、分享页、历史恢复和变化流都返回锁状态；`annotation_access.py` 白名单须同步。
  只读标记的“解锁”入口隐藏或禁用并说明原因；服务端也必须拒绝越权请求。
- 更新 API 可扩展现有按 ID PATCH：只修改锁状态时不携带旧 geom。
  新 UI 对持久对象编辑/锁定请求始终传 expected_revision；不要让客户端可选 CAS 造成互相覆盖。
- 数据层在同一事务、行锁内检查权限对应上下文、revision 和 geometry_locked；
  锁定时拒绝几何变更和删除，返回明确 `annotation_locked`。使用与项目错误格式一致的 409。
  同一请求不允许 `geometry_locked:false + geom` 绕过显式解锁步骤。
  前端必须按错误码区分 `annotation_locked` 与 `revision_conflict`，不能沿用当前
  “所有 409 都当版本冲突”的显示逻辑。错误回应前仍先做读取/写入权限验证。
- 注意 metadata 保存目前 `commitAdminEdit` 总会附带 geom：必须拆开差量更新，
  否则锁定后连改备注也会被当成移动拒绝。
- 锁定只是标记操作防误改。切片删除、账号删除等既有生命周期清理不受此锁阻挡。
  撤销也要过锁与 revision，不能绕过另一位用户后来加的锁；必要时提示先解锁。

### 6.4 保存失败、冲突和权限

- 有效拖动松手自动保存，显示轻量「保存中 / 已保存」；临时框仍由用户显式保存为标记。
- 请求失败：保留服务端最后确认的几何和本次草稿，标明“未保存”，支持重试/撤销。
  不在后台无限重试，不显示成功；网络等待期间不要启动第二个有歧义的写手势。
- 409 revision_conflict：保留本地修改草稿，读回服务端版本供比较；不以旧几何覆盖远端。
- 编辑中他人锁定/删除：结束手势并说明原因，不能强行补发旧 PATCH。用既有变更流同步；
  即使变更流迟到，服务端写入检查仍是最终依据。
- 临时查看到期/只读分享/权限撤销：保留用户可读的错误反馈，禁用写操作并遵循已有清屏规则。
- 所有位置修改形成一条撤销记录，使用服务器返回的新 revision；保存未完成前不宣称可撤销成功。
