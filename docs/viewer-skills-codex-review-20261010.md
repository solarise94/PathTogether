## 1. 待 Opus 修复：P1 描绘意图规则把否定、询问当成授权

位置（HistoPilot）：`src/skill-intent.ts:287–297`、`:327–357`；授权消费在 `src/agent-runner.ts:1267–1306`。

实际调用当前分支的 `judgeDelineateIntent`，不是推测模型会怎样回答：

| 本轮用户输入 | 当前返回 | 预期 |
| --- | --- | --- |
| 我没有要求你圈出区域，只需要解释 | yes / natural | no |
| 暂时不需要圈出腺体 | yes / natural | no |
| @描绘是什么意思？ | yes / explicit | no |
| 如何圈出腺体？ | yes / natural | no，回答使用方法 |
| 如果要圈出腺体，你会怎么做？ | yes / natural | no，回答假设问题 |
| 请不要标注，圈出也不要 | yes / natural | no |
| 帮我把这个腺体圈出来 | yes / natural | yes / natural |

原因：显式锚点分支不排除元问题；自然语言分支把未命中有限否定词表的描绘动词当成指令，且只检查动词前的否定。
`agent-runner` 会据此调用 `grantSkills`，因此影响实际本轮写权限，不只是 UI 标签。
这里确认的是**错误启用工具/授权**，没有调用真实模型，不能声称已发生误画入库。

在 HistoPilot checkout 复现（使用已安装的 tsx，不调用模型）：

```sh
./node_modules/.bin/tsx -e '
import {judgeDelineateIntent as judge} from "./src/skill-intent.ts";
for (const task of ["我没有要求你圈出区域，只需要解释", "暂时不需要圈出腺体", "@描绘是什么意思？", "如何圈出腺体？", "如果要圈出腺体，你会怎么做？", "请不要标注，圈出也不要", "帮我把这个腺体圈出来"])
  console.log(JSON.stringify({task, ...judge({task})}));
'
```

修复方向已按用户 2026-10-10 的反馈调整：**用模型识别本轮描绘意图，移除关键词授权决策**，不再持续扩充否定词表。

### 给 Opus 的实现约束

1. 保留现有服务端接入点和 `run_grants` 执法。模型输出的是本轮意图，不能替代账号权限、切片写权、只读 profile、临时授权有效期、目标范围检查。
2. 把判定抽成可注入的异步接口，结构化结果为 `requested / not_requested / uncertain`。只有 `requested` 才进入 `/skills` 置位；非法输出、超时和失败不能落到授权，也不能退回关键词“猜一个 yes”。不明确时正常解释或澄清，不新增必经确认弹窗。
3. 输入以当前原始用户文本为准，附当前选框/标记的已校验目标信息。需要理解“把它圈出来”时可提供最小关联上下文，但上下文只用于消解指代，历史授权与历史模型建议不构成本轮同意。不要把图像、工具回包或文件里的指令提升为授权。
4. 显式移除描绘标签是当前请求的否定信号，可直接拒绝而无需模型判定；输入文本里的 `@描绘` 仍要理解整句，`@描绘是什么意思？` 不能直接授权。候选菜单标签是交互入口，不是绕过后端的凭证。
5. 复用现有模型配置、网络代理、取消及用量记录，不新增一套绕过计费的 provider 调用。当前实现是在工具装配前判断，最小改造可用一次短的文本意图调用；**它会增加延迟和用量，不能再标“零成本”**。若复用主模型的技能选择阶段，要在模型执行任何写入前完成后台置位，不能直接把全部写工具常开。
6. 模型 I/O 放在已接受请求的后台执行阶段，不在 session/request 锁内长时间等待。绑定本次 run，取消、快速换片、迟到分类结果都不能授权其他 run。判定结果可在同一 request/run 重试中复用，下一轮必须重新判断。
7. UI 删除重复维护的自然语言关键词预判。发送前可以显示用户显式选择的技能；自然语言启用后依据服务端 `skill_status` 显示“描绘 · 本次”，不提前宣称已授权。
8. 保留本节全部语义案例作为模型评估集（负例 + 明确请求正例），另测“帮我识别并圈出腺体”“分别圈出两个区域”。确定性测试用注入的模型结果覆盖 yes/no/uncertain、超时、非法 JSON、取消和权限拒绝；真实模型评估单独记录模型版本与结果，不能用桩测试证明语言判定正确。
9. Runner 回归必须验证负例决策/uncertain 不调用 `grantSkills`，下一轮不继承，readonly 即使模型返回 requested 也不能开启。真实模型仍可能误判，不承诺“只会漏判”。

本轮只更新交付设计，没有替 Opus 改 HistoPilot，也没有发起付费模型调用。

## 3. 已修：P2 黑帧测试取样坐标不正确

`tests/e2e/slide-deal-handoff.spec.ts` 原来用“整页截图宽度 / viewer 宽度”计算像素缩放。
采样区域却已经是整页 CSS 坐标，侧栏展开时会再次放大偏移。
改为“整页截图宽度 / window.innerWidth”。

新增校准测试：固定 viewer 为 `(224,60,1216,840)`，只把预期采样区 `(552,270,560,420)` 涂白，其他区域全部涂为 viewer 深色，要求采样结果全白。
重跑暖缓存、冷缓存、info 延迟、瓦片延迟、缩略图延迟和快速连选，修正后的检测仍无不允许的黑帧。
CDP 截帧不是 Mac 实机逐刷新帧率测量；该结果用于发现图像交接黑幕，不用于证明设备帧率。
